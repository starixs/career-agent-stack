# 网申自动验证：配置与验收

## 当前能做什么

已接到同一个产品执行入口：聊天/后台批量的 `drive` 在填前、翻页前处理验证；**已批准的** `submit` 在提交前和提交后处理验证。验证完成后重新观察页面继续，不重复点击提交。未批准的动作仍不能提交。

- 手机号、邮箱地址取现有私密资料；按站点模板填接收账号、发码、等新码、回填（支持单输入框或拆位输入）、点击登录/验证、检查成功标志。
- 短信复用 Global 手机蓝牙服务，精确匹配签名、手机接收时间与本机到达时间，同一短信只能消费一次。配对的手机号码需由用户配置确认，MAP 不能可靠读出本机号码。
- 邮箱复用已连接账号的本机授权码。发码前建立只读 IMAP 会话并冻结 UID 基线，只读新 UID，核对精确发件人、接收账号和 IMAP 到达时间。不会改变普通邮件同步游标或已读状态。码邮件不进求职归档库/模型。
- 图形验证复用 `@career/captcha`（字符、点选、滑块、浏览器检查），有尝试预算和冷却。隐藏旧控件不会继续触发，短信/邮箱 OTP 不送图形 OCR。
- 同一部手机跨网站串行收码，邮箱按账号串行；页面同一模板只发送一次。超时、账号不一致、取消、暂停、接管、关页、无法确认成功时转人工，不自动重发。

**这是可配置的接入，不是已验证的全站覆盖。** 当前没有真实招聘站选择器模板/成功率数据。云端邮箱凭证模式、扫码、人脸、验证器、跨域 iframe、需要额外协议勾选的注册页仍需人工；不伪造云端 OTP API，不自动接受协议。图形验证也不能保证通过。

## 开发/定向验收配置（不是最终用户的产品步骤）

**浏览器接入现已由产品自动完成。网站模板覆盖与收码授权的完整产品开通流程尚未完成，不能把下面的 JSON/选择器工作转交给最终用户。**

1. 启动桌面，产品自动准备浏览器并装载扩展；现场与外部窗口是同一页，不需要用户开启开发者模式或加载扩展。
2. 在私密资料填写手机号、邮箱。在「手机连接」配对并允许读取短信，确认状态为 connected；在邮箱连接页连接**与网申资料相同**的本机邮箱。
3. 把 `app/docs/verification.example.json` 复制到 `$CAREER_DATA_DIR/verification.json`；未设置环境变量时是 `~/.keystone/career/verification.json`。建议文件权限 `0600`，不要提交真实配置。
4. 将示例站点替换为目标站点，确认选择器和成功标志，最后改 `enabled: true`。配置每次启动一次填表/提交时读取，不需要把密钥放进 JSON。

示例文件的 example.com/example.org 和选择器都是演示值，**不能直接投递**。不要在聊天或仓库里填写邮箱授权码、验证码。

| 配置 | 要求 |
|---|---|
| `origin` | 精确 HTTPS origin，不带末尾 `/`，不同子域分别配置；不会把码填到跳转后的其他 origin |
| `pathPrefix` | 模板适用的路径前缀，同一 origin 的模板不要重叠 |
| `channel` | `sms` 或 `email` |
| `recipientSelector` | 唯一可见、可编辑的手机号/邮箱 input；已有其他账号时不会覆盖 |
| `codeSelectors` | 一个完整验证码 input，或按顺序列出每一位 input；拆位数量必须与码长相同 |
| `sendSelector` | 唯一可见的「获取/发送/重新发送验证码」按钮（也支持 Send/Get/Resend code）；每次只点一次 |
| `confirmSelector` | 可选，仅接受明确的「登录/验证」按钮文案；不能配置为申请/提交按钮。自动校验的输入框可省略 |
| `successSelector` | 验证成功后才出现的唯一可见标志，不能选常驻页头或 body；仅填入码不算成功 |
| `smsSignature` / `smsRecipient` | 短信完整【签名】内的文本，以及配对手机的号码；号码必须和私密资料一致 |
| `mailSender` | 验证码邮件的精确发件邮箱，不能填域名通配符；仅本机 IMAP 连接可用 |
| `timeoutMs` | 一轮验证期限，5–120 秒，默认 90 秒；包括排队、连接和等码时间 |
| `captcha` | 是否尝试图形验证；失败仍可接管 |

只校验格式、不触发任何发码：

```bash
cd app/shell
node --import tsx/esm scripts/career-verification-check.mjs
# 或检查一个指定文件
node --import tsx/esm scripts/career-verification-check.mjs ../docs/verification.example.json
```

停用：将 `enabled` 设为 false 后开始新的运行。停止正在等码的任务用产品的暂停/停止或接管；不必删除手机、邮箱连接。单页已经发送过码后，重跑不重发：请人工处理本页，或明确重新打开一页开始新的验证。

## 批量测试之前的门槛

1. 先各跑一份短信、邮箱小样：确认接收账号、成功标志和后续填写；默认停在提交前。先不要开大型批量。
2. 注入旧码/错误签名或发件人：不得回填；断开手机或邮箱：不得先发码；等待时接管/暂停：不得再键入。
3. 两站同签名并行：收码必须串行、不得串号；同站重试不得连发短信。
4. 小样通过后，按产品现有审批/auto 模式选择是否真实投出。单次提交后只观察结果；不明结果应人工核对，不能重新批量提交来“测一下”。
5. 再扩大到一小批不同平台，统计自动通过、转人工、超时、填写失败、最终提交成功；有真实样本后才谈「绝大多数」。

## 自动测试边界

新增测试覆盖引擎续跑、已批准提交后的验证及不重复提交、DOM 按钮和 origin 限制、拆位输入、OTP 私密过滤、短信精确关联/一次消费/取消、IMAP UID 基线/发件人/体积/断连、普通邮箱同步不归档验证码。

可见浏览器小样（真实 DOM，固定收码替身，不触碰真实账号）：

```bash
cd app/shell
node scripts/career-verification-browser-smoke.mjs
# 经真实产品浏览器和扩展的更完整验收（先启动桌面自动准备资源）
node --import tsx/esm scripts/career-product-browser-smoke.mjs
```

两种小样（短信/邮箱）都确认 `changed`、恰好发码一次、收码资源释放。前者使用 Ego Lite；后者使用产品实际启动器、真实 Chrome 扩展及隔离 profile，另验证重启后自动连通且保留本地登录标记。两者都不是真实手机/邮箱收码或招聘站验收。

替身与 DOM 测试不等于真实手机、邮箱、扩展、招聘站整链验收。后续实机仍需用户完成以上配置；当前没有执行真实网申或大型批量测试。

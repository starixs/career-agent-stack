# 产品架构契约（所有包必须遵守）

产品 = `shell/`（keystone 基座的产品分支）+ `packages/*`（求职领域库）+ `skills/`（提示词技能包）。

## 产品决策（已定，不再讨论）
1. **单一对话**：只有一个"个人助理"对话区，没有多会话 / 工作区 / 多 Tab。一级入口是围绕时间与状态的五个面 + 指南：**今日、收件箱、卷宗、素材、复盘、指南**（2026-10-03 重构，见《产品落地计划》§11；经历库 / 简历 / 岗位与投递 / 面试 / Offer / 调研降为面内视图）。
2. **所有功能在产品内完成**；LLM 唯一的外部动作是 Web Search。
3. **内置国内模型，零配置**：OpenAI 兼容接口，默认 DeepSeek（可在打包时切换 Qwen / 豆包 / Kimi / GLM）。用户端没有任何模型设置项。
4. **反检测进产品，以真实浏览器为主**（"像真人用自己的浏览器"，架构以 lsdefine/GenericAgent 的 TMWebDriver 方案为主）：**主通道是用户日常 Chrome**——装一次 career-bridge 扩展（`browser-host/extension-bridge/extension/`，chrome://extensions 未打包加载），扩展 background 主动连入 sidecar（ws://127.0.0.1:18775），页面零自动化痕迹（无 CDP-at-launch、无 `--enable-automation`、`navigator.webdriver` 在 document_start 被删、CSP 响应头被 declarativeNetRequest 剥掉、弹窗中和），登录态 / Cookie / GPU / WebGL 指纹 / 历史全部是真的。桥能力经 `/api/career/browser/run {op:'bridge'}` 暴露：`tabs`（列真实标签页）、`solve_captcha`（在真实标签页上过验证码，通过率最高）、`sync_cookies`（把真实登录态灌进托管 Context）、`exec`（主世界 JS 兜底）。**托管 Chrome 是辅通道**（批量并行、用户没装扩展时）：真实 Chrome 持久 profile、去自动化标志、拟人节奏、限速与风险锁、被动捕获不注入请求、CDP `Fetch` 域剥 CSP 头（`browser-host/csp-strip.ts`）。**简单验证码 AI 先自己过**（图形字 / 点选 / 滑块 / 环境检查的复选框，`@career/captcha` + `career/captcha-solver.ts`，点选走"截图叠编号网格报格子号"，有站点预算与冷却，见第 8 条 L2.5），过不了再交用户；登录 / 2FA / 短信码 / 需本人作答的测评 / 最终提交 一律交给用户本人。不做 UA 伪造、不换代理、不做多账号。
5. **提交的介入程度**（2026-10-09 改定，取代"提交永远过人"）：`submit` / `send_greeting` / `answer_open_q` / `send_mail` 入队一律是待审（`ACTIONS_REQUIRING_REVIEW`，入队时不能自动批准）。网申提交另有两条免审路径，都由 `career/submit-policy.ts` 的 `decideSubmit` 裁决、批准人记在 `approved_by`：**auto 模式**（用户在岗位页打开 / `apply_auto_mode`）填后检查全部通过就批准（`auto`）；**自学习免审**（同一张表 `formSignature` 用户连续 3 次没改直接批准且提交成功，并且这次的简历文件哈希与开放题答案哈希都和上次用户批准时一致）批准为 `learned`。填后检查有任何需要人看的项（必填为空 / 值没生效 / 站点报错 / 附件没回显 / 待补 / 草稿）都不免审。页面上被改过、提交失败、被拒绝，计数清零。邮件、招呼语、开放题仍然只能由用户批准。
6. **不编造**：经历库里的主张默认 `pending`，只有用户确认或有强证据才能进简历；缺数据标"未知"。
7. **私密信息不进模型**（`@career/core` 的 `Vault`）：真实姓名 / 手机 / 邮箱 / 证件号 / 住址、投递网站账号密码、经历的保密细节只在「私密信息」页由用户填写，AES-256-GCM 加密落 SQLite（密钥 `CAREER_DATA_DIR/vault.key`，0600）。模型侧只有 `vault_status`（字段名 + 脱敏预览），文本里用占位符 `{{vault:profile.phone}}` / `{{vault:exp.<经历id>.<字段>}}` 指代。两个 hook：**出口**（填表 / 登录代填 / 导出简历时在 Node 侧 `resolve` 成明文并写访问日志）与**入口**（所有 career 工具结果回传前 `redact` 把明文换回占位符）。登录代填只填账号密码输入框、不点登录，仍遵守第 4 条。
8. **浏览器执行分层**（`@career/apply` 的 `driveApplication`）：L1 DOM 直驱（抽字段 → 规划 → 填写 → 读回核对）；L1.5 页内执行器（借鉴 quillfill：按 UI 框架指纹走 antd / element / iview / layui / 美团 / 饿了么 / Fusion / My97 等下拉与日期控件的"打开 → 等渲染 → 文本匹配 → 点选"，原生控件 React 安全赋值；配字典归一、日期格式推断、几何标签兜底、站点映射记忆、向用户学答案）；L2 视觉兜底（DOM 抽不到字段 / 填不进去 / 找不到按钮时：截图 → `Perceiver`（DOM 盒子 + macOS Vision OCR，按标签位置合成输入框；可选视觉模型做分类）→ 坐标点击 + 键盘输入，按钮文案做 OCR 容错）；L2.5 验证码自己过（`career/captcha-solver.ts` + `@career/captcha`：图形字 / 点选 / 滑块拼图 / 旋转走"截图叠编号网格 → 视觉模型报格子号 / 刻度号 → 代码换算坐标操作"，视觉模型不报像素（投递引擎 VlmPerceiver 的实测经验）；浏览器环境检查（Cloudflare Turnstile / reCAPTCHA 复选框）先 CDP 可信点击验证框再等放行。**可信输入**走 CDP `Input` 域三事件序列（mouseMoved → mousePressed → mouseReleased，50–100ms 间隔，`@career/captcha/human-input`，hover 依赖组件不能省 mouseMoved）。**预算闸**（`@career/captcha` 的 `CaptchaPolicy`，`career-browser` 路由的 `runSolveCaptcha`）：单站点当天最多 6 次自动尝试、连败冷却 10 分钟，超了 / 冷却中直接请用户；单次求解内最多 2 轮。短信码、认不出的类型、以及**最终提交前**的验证码永远交用户）；L3 交给用户（`describeObstacle` 说清要做什么：滑块 / 点选 / 短信码 / 图形码 / 浏览器检查，登录可先代填）。感知器只回答"哪里有什么"，点哪里填什么永远是确定性代码，提交类按钮任何一层都不点。风控：限流提示 / 跳转到验证页 → 风险锁按当天次数渐进退避（30 分钟 → 2 小时 → 12 小时 → 24 小时）。重复分区（教育 / 实习 / 项目"表格"）：按锚字段切行、逐行填、不够就点"添加"只填新出现的那一行。接管交还后由 `apply_continue` 从当前页继续。每个动作都是"动作 → 按用户可见的显示值读回核验"：核验不过就回滚并留空，标"需要你补"和原因码（宁空不错），只读与自定义控件不许原生硬写，⌘A / 回车只在焦点确认落在目标可编辑框时才按。障碍层（`blockers.ts`）在每页开始、上传后、每个分区前、字段被遮挡或超时后扫描遮罩 / 模态框：已知规则先处理（如"是否解析简历附件"选仅上传），未知的让模型在安全按钮里选，涉及同意协议 / 提交 / 付费的交给用户。详情页的入口按钮（立即申请等）可以点进申请表，最终提交仍任何一层都不点。每次运行把逐步记录、截图（敏感值打码）、失败字段的 DOM 片段和汇总写到 `$CAREER_DATA_DIR/runs/<动作id>/`，保留最近 50 次，供复盘迭代。提交卡只在必填全部核验通过且没有待补 / 不一致时才入队，否则发"还差 N 项要你补"。真实 Chrome 冒烟：`shell/scripts/career-browser-smoke.mjs`（不依赖 Tauri 能力令牌）。
9. **可视 + 长程**：用户随时能看、能关、后台不停。「浏览器现场」页签（`career-live`）从 Global 侧车拉 CDP screencast 帧（`/api/career/live/stream`，渲染层原生 fetch 直连 Global 端口，因为 Rust 代理不流式），画面只读；「接管」前置真实 Chrome 由本人操作，「交回」关闭等待中的接管让后台继续。批量投递由 Global 后台运行器（`career/batch-runner.ts`）执行：已批准的 fill_form 排队，用 p-queue 并行 drive（`CAREER_BATCH_CONCURRENCY`，缺省 2、上限 4；不同网站同时填、同一网站严格串行、同站两份之间拟人停顿；每份在自己的页面上，有等用户处理的接管时画面不被新开的网申抢走）、遇接管等用户交回自动续跑、两份之间拟人间歇、平台风险锁跳过、每日上限、状态与命令持久化在 kv（侧车重启自动续跑）。Global 事件经内部 `LiveHub` → stream → 渲染层 `CareerLiveBridge` 转发到 eventBus（Global 的 SSE broadcast 没有客户端）。浏览器宿主新增免令牌的 `withProductSession`（仅同进程调用）。
10. **浏览器只在产品里出现**：托管 Chrome 仍是 headed 真实 Chrome（反检测），但默认"内嵌窗口"（`CAREER_BROWSER_WINDOW=window` 退回独立窗口）：启动参数关掉遮挡 / 后台节流，Registry 用 CDP 把每个窗口停到屏幕角落（macOS 会夹回只露一小角）。macOS 的角落停靠永远会露 40px（系统规则：窗口必须留一截在某块屏上，CDP 和辅助功能接口挪窗都一样），启动参数里的屏幕外位置也会被忽略、窗口先在主屏整块弹出，所以 macOS 不靠角落：**缺省停靠在虚拟屏上**（`CGVirtualDisplay`，`CAREER_BROWSER_WINDOW=corner` 退回角落）——虚拟屏只和别的屏碰一个角、不共用边（共用边鼠标就能滑进去），按全部屏幕挑位置并核对系统实际给的位置，插拔 / 重排显示器后再核对。原生部分是 `browser-host/native/career-window-helper.m`，构建期由 `scripts/prepare-window-helper.mjs` 预编译成双架构并签名打进安装包（用户机器上不现场编译：没装命令行工具时调 clang 会弹系统对话框）。**焦点守卫**（同一助手的 guard 模式，`CAREER_BROWSER_FOCUS_GUARD=0` 关闭）：托管 Chrome 启动、开新页、网页弹窗都会被系统激活成前台应用，哪怕窗口看不见用户打的字也会落进网页——守卫按 `--user-data-dir` 认领托管 Chrome，一被激活就把焦点还给之前的应用（几毫秒，肉眼只见前台窗口红绿灯闪一下灰），渲染层 `focusGuard.ts` 留作助手不可用时的后备。**隐藏兜底**：虚拟屏建不出来 / 中途消失 / 重排后挪不开时，守卫用 `NSRunningApplication` 把托管 Chrome 整个隐藏（osascript 隐藏的一开新页就被取消隐藏）。隐藏后 DOM、点击、计时器照常、页面仍报 visible，但 Chrome 不合成画面：普通截图和 screencast 都会挂住，所以借用代理把 `page.screenshot` 换成 `fromSurface:false`、现场画面改为约 300ms 轮询；隐藏期间新加载的文档和后台标签页连 `fromSurface:false` 也会挂住，截不到时给页面一次 `Page.bringToFront` 即恢复（Chrome 仍隐藏，守卫还焦点）。不用最小化——同样不出帧。真机冒烟：`shell/scripts/career-vdisplay-smoke.mjs`。**浏览器常驻**（缺省开启，`CAREER_BROWSER_RESIDENT=0` 关闭，仅持久 profile 生效）：空闲不再按 15 秒宽限拆除 Context——每个任务重新启动 Chrome 会带来 Dock 弹跳、窗口闪现、焦点被抢；常驻后 Chrome 只随显式关闭（browser_close / 会话退休 / 进程退出 / 用户自己关掉）退出。用户在聊天旁的现场抽屉（`CareerLiveDrawer`，可全屏）里看和操作：点画面即接管，点击 / 输入 / 滚动经 `/api/career/live/input` 转发；接管不再前置真实窗口。页面弹出的系统选文件框由 Playwright `filechooser` 拦下（`career/file-chooser.ts`），抽屉里出现「选择文件」，内容经 `/api/career/live/file` 交回 `chooser.setFiles`。画面里处理不了的情况（插件弹窗等）用 `/api/career/live/window` 临时显示真实窗口，用完收回。
11. **对话是主场，卡片就地完成**：一级入口只用来看。凡是要用户动手的一步，工具都推 SSE `career:card {sessionId, card:{id, kind, title, data}}`（Session 侧，进 renderer 白名单），TabProvider 按 id 去重存进 `careerCards`，`CareerChatCards` → `CareerFlowCards` 在对话里渲染。卡片种类：`vault_missing`（vault_status 发现缺核心资料）、`needs_user` / `drafts`（apply_run / apply_continue 的填表缺项与开放题草稿）、`site_login`（卡在登录页且私密库没有该站密码）、`claims_confirm`（experience_add）、`resume_diff`（resume_tailor）、`mail_bind`（还没绑定邮箱）、`review`（待你批准的提交 / 发送，id=`review:<动作 id>`，提交卡内嵌审阅清单；Global 后台推的 `career:review` 由渲染层按同 id 合并）、`apply_gaps`（停在提交前但没过提交门槛：还差 N 项要你补），外加批量投递进度卡（Global 事件桥的 `career:batch`）。卡片里填的值走产品接口直接落库：资料、账号密码进私密库，答案进答案库（question_key 用表单标签，下次填表命中），邮箱授权码进本机凭据文件。完成后用 `suggestToChat` 发一句"已补齐，请继续"给助理，值本身不进对话。卡片持久化在 career 库的 `chat_card` 表（id 为稳定领域 id，同 id 覆盖并回到 pending），并锚定到产生它的工具调用：career 工具注册时包一层 AsyncLocalStorage，从 Claude Code CLI 传入的 `extra._meta['claudecode/toolUseId']` 取 tool_use id，`card()` 落库并随 SSE 带上 `toolUseId`。渲染层会话打开时 `GET /api/career/cards?session_id=` 读回，经独立的 `CareerCardsContext`（避免流式输出时所有消息重渲染）交给 `Message.tsx`：卡片渲染在它那次工具调用所在的回复下面；完成（completed）/ 稍后（dismissed）后折叠成一行，`POST /api/career/cards/:id/state` 落库，跳过的可重新打开。对话底部只放没有锚点（后台批量等）或锚点不在已加载消息里的待处理卡片，不再堆叠。
12. **外部依赖在产品里配置**：模型 Key 存内置 provider `career-llm` 的 `providerApiKeys`（`resolveProviderEnv` 本来就是"保存的优先、构建常量 / 环境变量兜底"），搜索 Key 存 `providerApiKeys['career-search']` + `careerSearchProvider`（`career/setup.ts` 解析，优先于环境变量）。入口：设置 → 通用 → 求职助理：模型与搜索，以及对话底部的配置卡（缺模型 Key 时必需卡；缺搜索时可"暂不配置"的建议卡；web_search / company_research 发现没配置时推 `search_setup` 卡）。`GET /api/career/setup` 只回状态与来源，不回 Key。`start_desktop.sh` 不再强制环境变量。工具侧的模型调用（`ShellLLM`）对非 Claude 模型显式 `thinking: disabled`、默认 8192 输出上限，只有思考块没有正文时报明确错误（此前 DeepSeek 默认思考吃光 4096 输出，工具报"模型回复中没有 JSON"）。
13. **简历工作台 = resume-studio**：`packages/resume-studio`（`@career/resume-studio`）引入 resume-studio 的文档侧——Zod 4 `ResumeData`、15 套 react-pdf 模板（中文走 Noto Sans/Serif SC 兜底、分区标题按 zh-CN 本地化）、样式规则、字体清单。内容权威仍是 `resume_*.schema_json`；工作台文档存 `resume_design`，`career/resume-studio-convert.ts` 双向转换并按条目 id 合并（部门、claim_ids、项目角色等工作台表达不了的字段不丢）；内容被工具改过就按新内容重建、保留排版；自动保存回写内容，快照 10 分钟最多一次。渲染层 `components/resume-workbench/`：左栏内容（拖拽排序、显隐、复制、结构化要点编辑、证件照）/ 中间实时预览（浏览器内 react-pdf → pdf.js）/ 右栏模板与设计（模板缩略图、主栏侧栏版式、字体、配色、页面）；撤销重做、窄屏变标签页；素材面与聊天旁抽屉共用。私密库占位符留在文档里，预览明文由接口单独给。字体：渲染层 CSP 不能直连 CDN，走 Global `/api/career/live/font?u=`（白名单 + `$CAREER_DATA_DIR/fonts` 缓存）；侧车导出 PDF / 图片用同一套模板（Word 仍按内容生成）。Vite `resolve.dedupe` 去重 react，否则包内模板与 react-pdf 各用一份 React。resume-studio 对 react-pdf / fontkit / react-pdf-html 的 4 个保真补丁暂未引入。

## 包约定
- 语言 TypeScript，ESM，NodeNext；`tsc -b` 可编译，`vitest` 可测，测试放 `packages/<pkg>/test/*.test.ts`。
- 只依赖 `@career/core` 提供的：`Db` / `Repos`（SQLite 仓储）、状态枚举、`LLM` 接口（`complete({system, messages, json})`）与 `FakeLLM`、`extractJson`、`loadSkill/skillPrompt`。
- **不直接依赖任何模型 SDK**。需要模型就接收一个 `LLM` 实例。
- 中文优先：提示词、错误信息、日志都用中文；输出结构字段用英文。
- 需要浏览器的代码接收 `playwright-core` 的 `Page`，并额外提供一个可被 fake 的 `PageLike` 最小接口用于测试；**不自行启动浏览器**（浏览器由 shell 的 browser-host 托管）。
- Python 模块（trident-scanner / docparse / intel-compass）只通过子进程或本地 HTTP 调用，不改它们的源码；路径与端口从环境变量读（见根目录 `.env.example`）。
- 新增依赖：在包目录 `pnpm add <pkg>`；若遇 lockfile 冲突等几秒重试。
- 每个包的 `src/index.ts` 导出公开 API，并在包根写 `README.md`（200 字内：做什么、怎么用、哪些是未实测的）。

## 数据模型
见 `packages/core/src/db/schema.sql`（版本 1 基线）+ `packages/core/src/db/migrations.ts`（增量迁移）。**改已有表的结构只能新增迁移**：版本号递增、只追加不修改，`BEGIN IMMEDIATE` 里执行（两个侧车同时开库也只跑一次），加列用 `addColumn`。新表可以写进迁移，不要再往基线里加列。

**审批绑定内容**（迁移 v2）：`action_queue.content_hash` 是 payload 规范化 JSON 的 sha256；`reviewActions` 只处理 `pending_review`，批准时记 `approved_hash` 与 `approved_by`（user / auto / learned / system）；执行方一律先 `claimAction(id)`——原子地 approved → executing 并核对哈希，内容变了就退回待审，已被认领 / 已执行的拿不到（防重复发送、防批量与对话双跑）。改内容用 `updateActionPayload`（批准失效），失败或浏览器关闭后重排用 `requeueAction`（批准仍有效）。
**投递材料包**（`application_packet`）：`apply_prepare` / `mail_compose` 入队前把简历冻结——内容进 `resume_snapshot`，PDF 按内容哈希存 `exports/packets/<sha256>.pdf`，JD 原文进 `jd_snapshot_json`；payload 只带 `packet_id`，执行时（对话、批量、邮件）从材料包取文件并核对哈希，对不上就停。选简历：指定 → 该岗位定制版 → 唯一主简历；多份主简历不替用户猜。
**稳定岗位键**（`job.job_key`）：`<platform>:<原站岗位号>`，没有就按规范化网址 / 公司职位地点哈希（`jobKey()`）；本地库与服务端岗位库共用这个身份，`remote_id` 记服务端 id。
**每份网申一个页面**（`career/app-pages.ts`）：带 `applicationId` 的浏览器操作落在这份网申自己的页上（借用代理每次是新对象，按 `page.mainFrame()` 识别同一页）；填完停在提交前的页面一直留着，直到提交成功或被拒绝（`releaseApplicationPage`）；等提交期间 `syncHandoffHold` 持有浏览器。页面锁按页：同一份网申不会被两处同时操作（`BROWSER_BUSY` 409，批量与 `apply_run` 收到后放回队列、不记失败），不同网申互不阻塞。现场画面跟随 `focusPage` 切到正在操作的那一页。
**填后检查与提交**：`driveApplication` 停在提交前时附带 `review`（`@career/apply` 的 `buildSubmitReview`：审阅清单 + `formSignature` + `openAnswersHash`），整份进 submit 动作 payload（批准即绑定这些内容）。提交只由 Global 的提交执行器（`career/submit-executor.ts`，3 秒轮询 + 审批后立即执行）在 `claimAction` 之后调用进程内 `runOperation('submit')`——HTTP 浏览器路由不开放 submit / release。`submitApplication` 是全仓唯一点提交按钮的代码：必填为空不点；成功文案或跳转且表单消失判 `submitted`（投递推进到 applied、页面关闭）；新校验错误判 `failed`（回到待审）；验证码判 `handoff`；没等到结果判 `uncertain`（不重试，等用户在等你条「投出了吗」确认）。提交前与页面比对得到的用户改动以用户为准写回答案库（`corrected` 事件）。
**岗位汇总表与匹配**（迁移 v4）：`job.employment_type`（校招 / 实习 / 社招）、`cohort`、`source_version` / `source_status`（服务端版本与下架 / 合并）、`match_json` / `match_score`。岗位来源统一实现 `@career/core` 的 `JobSource`（本地、campus-radar 静态汇总、服务端 `RemoteJobSource`；服务端契约见 `docs/SERVER-API.md`，客户端不直连数据库）。匹配是确定性的 `matchJob`：用户明确条件（kv `profile.job_prefs`：届别 / 学历 / 城市 / 类型）+ 已截止 → 硬条件，违反的不推荐（分数封顶 20）；JD 的硬性要求与关键词经技能同义词表（`SKILL_LEXICON`）逐条对到证据——只用已确认的经历主张与简历条目（pending 主张不算），回答"哪条要求对应你哪段经历"。框选确认投出走 `career/batch-apply.ts` 的 `applyJobs`（逐个冻结材料包、当场批准、交后台批量运行器；没有待投清单）。导出表格（`career/xlsx-export.ts`）每张表带稳定 id。答案改动回传由 Global 每 10 分钟上传一批（配置了服务端才传）。
**题库**（迁移 v5，R09）：`question` 是题目实体（`questionKey`：规范化题干，面试题再按公司区分；来源 public / seen / generated，被真实遇到就升级为 seen 并计次），`question_attempt` 是作答记录（绑定简历快照与岗位，记最近 / 最好得分）。`interview_questions` 出的题、`interview_retro` 复盘里被问到的题、`exam_practice` 的题与批改结果都自动进题库；`question_add` 补录用户见过的题，`question_attempt` 记模拟面试打分。
**过机筛**（R04）：kv `resume:ats:<id>` 打开后，这份简历的导出与投递材料包都用 `@career/resume` 的单栏、无照片 ATS 版（`renderPdf({ats:true})`），不用工作台模板；自检（`career/ats-check.ts`）按当前设置导出、用 pdf.js 抽文字，交给 `atsCheck` 对照内容（读不出 / 顺序被打乱 / 图标字体 / 照片 / 页数）。
**经历访谈进度**（R03）：kv `experience:interview` 记六轮普查每轮状态与下一轮问题，`interviewProgress` 再从经历库算缺口（没确认主张的经历、缺量化的主张、待确认数），跨对话延续。
**回答质量评测**（promptfoo，只在开发 / CI）：`evals/` 用自定义 provider 调产品真实流水线（简历改写 + 编造检测、岗位评估、出题、笔试批改），确定性断言在 `evals/asserts/checks.mjs`（自身有单测）。`pnpm eval` 需要 `CAREER_LLM_API_KEY`；样本全部是合成 / 脱敏的。编造检测已覆盖中文数字（含万 / 亿、百分之几）、以公司 / 大学等结尾的中文机构名、头衔与"带领 / 主导 / 独立负责"等说法。
**答案库治理**（迁移 v3）：`answer_bank.status`（active / pinned / archived）、`sensitivity`（`classifyAnswerSensitivity`：证件号 / 密码 / 是否使用 AI 作答 / 反机器人题为 `excluded`，永不存、不复用、不上传；自我认同与个人信息上传时不带值）。改答案时旧的停用保留历史。`answer_event` 是答案改动的上传队列（`uploaded_at` 为空即待传），服务端接口就绪后由同步任务上传。
状态流转见 `packages/core/src/states.ts`。私密信息库（`vault_item` / `vault_access_log`）与占位符规则见 `packages/core/src/vault.ts`。

## 五个面与闭环（shell 侧契约）
- **面板 → 对话**：面板按钮只能通过 `suggestToChat(text, context)`（`CareerPrimitives.tsx`）把话发进对话，事件 `career:chat-suggest` 由 Chat 订阅并真正 `sendMessage`；`context.refs` 里只放对象 id，由 `buildCareerContextReminder` 变成隐藏的 `<CAREER_CONTEXT>` 块。禁止再做"复制提示词"按钮。
- **对话 → 面板**：写库的工具 / 路由完成后调用 `focus()`（`career/intake.ts`）广播 `career:focus {surface, id, application_id, job_id}`；App 打开对应的面（`features/career-shared/nav.ts` 是面的唯一清单），面内自行订阅同一事件定位对象。
- **模型提案、面板处置**：任何需要用户决定的东西都要落成有状态的对象（待审动作、pending 主张、截止事件、收件箱条目、未确认素材），面板一键处置；模型不要在对话里逐条追问。
- **收件箱是唯一进水口**：粘贴 / 邮件 / 文件都先 `inbox_item`，再由 `captureIntake` 归档；新的来源接到这里，不要另起一套。
- **邮箱**：授权码只存 `$CAREER_DATA_DIR/mail-credentials.json`（0600），不进 SQLite、不进日志、不进对话；轮询只在 Global 侧车跑一份；发送只能由 `executeSendMailAction` 对已批准的 `send_mail` 执行。

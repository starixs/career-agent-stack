# 招聘网站自动登录手册

本手册沉淀真实浏览器、真实手机/邮箱收码和招聘网站登录的已验证做法。目标是：有限招聘站点逐站覆盖后，已覆盖站点全自动登录；未覆盖站点自动诊断、记录阻塞，不把尝试当成功。

## 1. 不变边界

- 只登录，不投递。登录成功不等于获得网申提交批准，提交仍走既有审批。
- 登录/注册页出现「我已阅读并同意」「用户协议」「登录政策」「隐私条款」「服务协议」等必选勾选时，**直接勾选，不逐站询问、不额外判断**。没有该控件就不制造勾选动作。
- 不复制 Cookie 到剪贴板，不把手机号、邮箱正文、短信正文或验证码写进日志、模型回执、站点 SOP 或仓库。
- 不用历史验证码冒充新码，不把发码倒计时、图形验证通过、资料已填或页面可打开计为登录成功。
- 扫码、人脸、密码、硬件验证器等未覆盖方式如实记录，不伪造通过，不无限重试。

## 2. 全自动登录状态机

按顺序执行，任何一步失败都保留当前页面和具体原因，不从头盲点：

1. **先检查现有会话**：已出现退出入口、个人中心，或登录表单已消失且已进入账号/简历页时，直接记成功，不再发码。
2. **匹配站点配方**：优先使用本手册已验证站点；未知站点只做探测，确认控件后再操作。
3. **选择登录渠道**：明确切换「短信登录 / 验证码登录 / 邮箱登录」。切换后必须重新观察，避免把密码页当短信页。
4. **预热调试器**：第一次拖动、截图或坐标操作前，先发无害 CDP 调用，等黄条布局稳定，再量坐标。扩展报告 not attached 时重挂后再量。
5. **准备账号和协议**：用私密资料占位符填手机号/邮箱；勾掉所有登录必需协议。隐藏 input、label、span 都可能是实际控件，最后读取 checked 或页面状态确认。
6. **先准备收码，再发码**：手机通过真实 OTP 需求唤醒有限重连窗口；邮箱先建立只读 UID 基线。通道未准备好就不点发码。
7. **只点一次发码**：观察按钮倒计时、toast、弹层和页面变化。没有倒计时不等于没有点击，先查「验证未通过 / 协议未勾选 / 控件被遮挡 / 风险拒绝」。
8. **处理图形验证**：根据真实 DOM 和截图分类，不能因页面有「获取验证码」就把所有验证归为 SMS。通过后重新观察是否已自动发码，未发才允许再点一次。
9. **等待新码**：按发送时间、精确签名、接收方和一次性消费关联；串行等待，迟到短信也算新码，不能因固定等待短就判没到。
10. **回填并登录**：受控输入框使用原生 value setter + `input` + `change`；必要时再勾选协议。只点明确的登录/注册按钮，不点申请/投递按钮。
11. **验证会话**：登录表单消失且进入账号/首页/简历/求职设置页，或出现退出/个人中心，才算成功。仍在登录页时先读错误提示，不宣称成功。
12. **沉淀非敏感配方**：记录渠道、公开控件锚点、验证类型、短信签名、成功证据和失败原因；不记录 Cookie、凭证、邮件/短信正文、OTP。

## 3. 协议勾选的实测规则

- 这是登录必选步骤，统一直接勾选。
- 常见位置：「我已阅读并同意」文字前面；可能是 `input[type=checkbox]`、隐藏 input、label、自定义 span。
- 勾不上时先确认控件进入视口。飞书招聘页可把登录容器临时上移，再用可信 CDP 坐标点击；完成后恢复布局。
- 点击后必须验证：`checked === true`，或对应「请勾选此项」错误消失。只看到点击回执不算勾上。
- 58 同城首次注册还可能出现「同意协议并注册」确认按钮，这是登录/注册流程的一部分，可以继续；它与岗位投递无关。

## 4. 实测问题与固定对策

| 实测问题 | 固定对策 |
|---|---|
| 首次 attach 后页面被黄条推下，按旧坐标拖动导致失败 | 先无害 CDP 预热，再重新测量。海投网滑块预热后一次通过 |
| 扩展标记仍 attached，但 Chrome 实际已 detach | 扩展自动重挂一次，再发送命令 |
| 切换短信 tab 后实际是密码页 | 以当前输入框和页面变化为准，不以点击成功为准 |
| 同页有隐藏和可见两份表单 | 只在 `getBoundingClientRect().width > 0` 的可见唯一表单操作。智通实测有隐藏重复表单 |
| 有短信输入框，图形验证被误分类为 SMS | 先检测 geetest/yidun/verifycenter 等真实容器，再决定验证类型 |
| 点选/滑块通过后按钮仍显示「获取验证码」 | 先看是否已自动发码；没有倒计时才再点一次，不连续消耗验证 |
| 点击有可信事件但没有倒计时 | 查短暂 toast。京东实测出现「验证未通过」，不是点击无效 |
| 受控组件回填后值被清空 | 用原生 setter 并补 `input/change`，不能用只写 DOM value 的方式 |
| 勾选框在首屏外，坐标点击无效 | 滚动/scrollIntoView/临时上移容器，再量再点 |
| 变化回执可能带账号或验证码 | 输入框只记 placeholder；其他文本对手机号、邮箱、4–8 位数字码脱敏 |
| 长 JSON 探测被 CDP 结果截断 | 探测直接返回对象，不要把整段结果先 `JSON.stringify` |
| 截图或脚本超时 | 换 `browser_cdp` 的 `Runtime.evaluate` 获取 DOM，不让单个工具失败终止整站诊断 |
| 手机仍连接但新短信暂未出现 | 在有限窗口内继续等新签名；不能把上一站短信填到当前站 |

## 7. 后续全量遍历规则

- 维护「已验证 / 阻塞 / 未测试」有限站点矩阵，每次只跑一个站点，避免手机与邮箱串码。
- 已成功站点优先复用现有会话；确实需要重新登录时按配方执行。
- 新站点只有完成真实登录后才升级为「已验证」；失败样本不能污染成功配方。
- 配方失效时先诊断控件、验证厂商和失败阶段，再局部修订，不重写整条链路。
- 全自动的含义是：已覆盖能力自动执行，未覆盖能力自动诊断和交接；不是无条件重试，也不是把阻塞改称成功。

# 目标
让助理记住的东西少而准：同一件事只留一条，过时的说法被新的取代。拿不准就不动。

# 输入
若干组候选，每组是同一 scope、同一类型、文字相近的几条记忆：`id / 内容 / 重要度 / 证据次数 / 更新时间`。

# 怎么判断是不是同一件事
- 算同一件事："用户希望先说结论" 与 "用户希望回复先给结论再讲依据"——说的是同一个要求，后一条更具体。
- 算同一件事："用户不考虑外包" 与 "用户可以接受驻场外包"——同一个偏好前后变了，属于矛盾，按约束 3 处理。
- 不算同一件事："用户希望先说结论" 与 "用户希望回复简短"——都和回复风格有关，但是两个独立的要求，合并会让其中一条变模糊。
- 不算同一件事："美团要扫码登录" 与 "美团笔试有性格测评"——同一家公司的两件事，各自有用。

# 约束
1. 只有确实在说同一件事时才合并；只是话题相近（都和"简历"有关）不算。
2. 合并后的 content 一句话、≤80 字、第三人称"用户……"，保留各条里不冲突的具体信息（数字、城市、公司、条件），不添加新信息，也不改写成更笼统的说法。
3. 两条互相矛盾时，以更新时间较新的为准，合并结果就是新说法（必要时注明"后来改为……"）；证据次数多的旧说法也不能压过用户后来的明确改口。
4. 不确定、或合并会丢信息时，这一组给 action=keep；宁可留两条相近的，也不要合成一条错的。
5. 只处理输入里给出的 id，不要编造 id，也不要把不同组的条目合到一起。

# 输出
```json
{
  "groups": [
    {"ids": ["mem_a", "mem_b"], "action": "merge", "content": "用户希望回复先说结论，三句话以内"},
    {"ids": ["mem_c", "mem_d"], "action": "keep"}
  ]
}
```

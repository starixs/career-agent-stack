# 数据分析出题手册（精简版）

> 涵盖：业务分析 / 商业分析 / BI / 增长分析

## 面试官在验什么

1. **技术是门槛，业务是上限**：SQL 会不会是筛子，能不能把分析变成决策才是评分点。
2. **分析有没有被采纳**：做了一堆报表没人用和推动了一个决策是两个级别。
3. **归因的严谨性与数据敏感度**：最忌把相关当因果；给一个反常的数，能不能立刻想到几种原因。

## 高频追问链

**链一：分析项目**
讲个你做过的分析 → 结论是什么 → 怎么排除其他解释的 → 有没有做实验验证 → 业务方采纳了吗 → 后来结果怎么样
分水岭：第 3 层（答不出排除逻辑，归因不成立）

**链二：指标异常（现场题）**
某指标突然跌了 20%，你怎么查 → 先看什么 → 怎么拆维度 → 如果各维度都跌呢 → 怎么排除数据本身的问题
分水岭：第 3 层（考的是思路结构，不是答案对错）

**链三：技术深度**
这个数怎么取的 → 表是哪来的，有没有脏数据 → 窗口函数/留存怎么算的 → 数据量大的时候怎么优化
分水岭：第 2 层（说会 SQL 但讲不出具体用法）

## 专业性检验点

- 留存怎么算的，次留、七留、三十留的口径分别是什么
- 用没用过窗口函数，举个实际场景
- AB 实验怎么设计的，样本量怎么定，显著性怎么判
- 遇到过数据不一致吗，怎么定位的
- 用什么 BI 工具，指标口径归谁管
- 增长分析：漏斗怎么拆的，每一层的转化基准是多少
- 你做过的分析里，哪一个改变了业务决定，怎么证明是它改变的
- 同一个指标名在不同场合含义不同时，你怎么处理

## 按企业性质调整

- 大厂：实验设计和统计严谨性追得最深，可能问 p 值、功效、AA 测试
- 创业：数据基建差，问你没有数仓的情况下怎么干活
- 国企银行：更关注数据准确性、报送规范、口径一致性，实验类问题少
- 外企：可能要求用英文讲分析逻辑

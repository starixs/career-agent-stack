# 产品经理复盘手册（精简版）

> 涵盖：C 端 / B 端 / 数据产品 / SaaS / 平台产品

## 面试官在验什么

1. **判断力，不是执行力。**为什么做这个不做那个，砍掉了什么，依据是什么。
2. **需求是怎么来的。**老板说的、竞品有的，还是自己从数据和用户那里挖的。
3. **上线之后管不管。**只讲上线不讲效果和迭代，说明是需求翻译员。
4. **和研发的真实关系。**推过硬仗的人说得出具体博弈过程。

## 高频追问链

**链一：需求判断**
为什么做这个功能 → 怎么确认是真需求 → 多少用户有这个问题、怎么量的 → 当时还有哪些方案 → 为什么选了这个 → 如果只能做一半砍哪块
（分水岭在第四、五层：答不出备选方案，`content:decision-rationale` 成立）

**链二：上线之后**
上线效果怎么样 → 核心指标动了多少 → 怎么确认是这个功能带来的 → 有没有灰度或 AB → 有没有指标变差的地方 → 迭代了几版
（只说好不说坏，面试官通常追"有没有负向影响"；分水岭在第三层）

**链三：协作**
研发说做不了你怎么办 → 具体怎么谈的 → 最后砍了什么保了什么 → 谁拍的板

## 特有丢分点

| 表现 | 标签 | 说明 |

| 需求来源是"老板要的""竞品有"，没有自己判断 | `content:decision-rationale` | 高频 |

| B 端讲不清客户的业务流程 | `content:domain-depth` | B 端面试核心检验点 |

## 专业性检验点

- 负责模块的北极星指标是什么，为什么是它
- 需求优先级怎么排，和研发怎么对齐排期
- PRD 评审时被挑最多的是什么
- 灰度怎么放，回滚条件是什么
- B 端：客户是谁、决策链是谁、实施周期、续费率
- 数据产品：指标体系怎么搭、口径归谁定
- SaaS：ARR、NDR、获客成本、流失原因

## 与企业性质叠加

- **大厂**：AB 实验、数据口径、归因追得最深
- **创业公司**：问没有研发资源时怎么把事推动起来
- **国企 / 银行**：更关注需求合规性、内部审批流程、跨部门协调
- **外企**：stakeholder management 是高频考点，追问怎么对齐不同区域诉求

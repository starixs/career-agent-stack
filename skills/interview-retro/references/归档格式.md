# 归档格式

> 每场复盘默认归档到产品的面试库，由产品持久化并跨场累积；用户不需要自己保存文件。本文件约定一场记录要落哪些字段、标签区怎么写、索引怎么维护、跨场分析怎么做。

## 一、单场档案字段

| 字段 | 取值 / 说明 |
|---|---|
| 公司代号 | 建议用代号（A 公司、B 公司），同一家公司前后代号一致；不保留面试官姓名和联系方式 |
| 公司性质 | 大厂 / 创业公司 / 国企 / 银行 / 外企 / 未知 |
| 岗位 | 12 类岗位之一；不在其中的写实际岗位名并标"无专用手册" |
| 轮次 | HR 面 / 一面 / 二面 / 终面 / 交叉面 |
| 面试官身份 | HR / 同级或一线主管 / 用人经理 / 总监及以上 / 交叉面 / 未知（可按轮次判定反推并标"推测"） |
| 类型 | 校招 / 社招 / 实习 |
| 语言 | 中文 / 英文 |
| 时长 | 实际时长与预定时长 |
| 日期 | 面试日期 |
| `result` | `none`（无结果）/ `rejected`（已拒）/ `advanced`（已进下一轮或 offer）/ `no_feedback_inferred`（无反馈、推测未推进） |
| `result_source` | `none`（无来源）/ `official`（官方通知）/ `inferred`（推测） |

## 二、本场标签区

跨场分析只读这一区和基本字段，不读正文，场次多了全文读取会超出上下文。

```
内容问题: content:metric-definition（数据口径）, content:attribution（归因剥离）
表达问题: delivery:no-structure（无结构）
追问性质: probe:verify×3, probe:clarify×1, probe:routine×2
卡壳最深层级: 第三层（归因）
观察到的信号: signal:overtime（面试超时）, signal:next-step-vague（结束语无具体信息）
```

- 标签必须来自标签词表，写成 `机器字段（中文展示名）`。自己造词会导致同类问题被记成不同名称，频次失真。
- 追问性质要记数量，格式 `类型×次数`；`probe:guide` 和 `probe:routine` 不计入丢分统计。
- 卡壳最深层级取项目深挖类的层级数字，没有项目深挖题时写"无"。

## 三、结果状态规则

- 只有收到官方通知（拒信、下一轮邀约、offer）才能写 `rejected` / `advanced`，`result_source=official`。
- 没有官方反馈时，`result` 只能是 `none` 或 `no_feedback_inferred`，且 `result_source=inferred`；同时在信号区记 `signal:no-feedback`。
- **禁止编造拒绝原因。**无反馈不等于被拒，更不能从"沉默"倒推出"因为哪题答砸了"。等待周期参考见各企业性质手册，且明确不能反推结果。
- 证据与推断分开写：材料里能看到的是证据，其余是推断；每条推断必须给出依据，并附至少一种其他解释。不用"说明""就是""一定""肯定"这类措辞。
- 用户后来收到官方消息时，把 `result` 改为对应值、`result_source` 改为 `official`，保留原推测记录以便对照。

## 四、索引结构

索引随每场归档整体更新，包含五部分：

1. **场次表**：日期 / 公司性质 / 岗位 / 轮次 / result / result_source
2. **重复出现的内容问题表**：标签 / 次数 / 出现场次
3. **重复出现的表达问题表**：标签 / 次数
4. **各岗位方向被反复确认的方向**：按岗位方向归纳该方向被验真型追问集中在哪里
5. **待补强清单**：需要补事实的（核实数字、想清归因）和需要改表达的分开列，可勾选

示例片段：

```
重复出现的内容问题
| content:attribution 归因剥离 | 3 | 08-06, 08-14, 08-20 |
| content:career-consistency 履历一致性 | 2 | 08-06, 08-20 |

需要注意的不一致：
离职原因在 08-06 说的是希望更大平台，08-20 说的是团队调整。
同一家公司的多轮面试之间，面试官通常会交叉核对。

各岗位方向被反复确认的方向
- 产品经理（2 场）：样本不足，暂不归纳
```

## 五、索引维护规则

1. **样本不足要写明。**同一岗位方向少于 3 场时写"样本不足，暂不归纳"，不从两场数据里总结规律。
2. **说法不一致要单独列出。**用户在不同场次对同一问题（尤其离职原因、职级、项目归属）说法有出入，写清楚两次分别说了什么。这是跨场归档能提供、单场复盘做不到的部分。
3. **已完成的待补强项打勾保留，不删除。**
4. **频次统计只以本场标签区为准**，不重新阅读正文。
5. 本场出现的标签在索引里已有记录时，报告里写明这是第几次出现，并列出前几次发生在哪一场。
6. 新一场复盘开始时，若待补强清单有未勾选项，提一次（"上次记着要核实 A 项目同期数据，这次用上了吗？"），用户不接就继续，不重复提醒。

## 六、跨场分析

第 3 场归档完成后主动提一次"已存 3 场，要不要一起分析"，之后不再主动问。三场是门槛，两场看不出规律。输出三部分：

1. **按标签统计**：哪类问题出现最多、有没有随场次减少
2. **按岗位方向**：这个方向的岗位被反复确认的是什么（满 3 场才做，否则写样本不足）
3. **优先级建议**：重复次数最多的前三项，作为下次面试前的准备重点

跨场分析同样只用证据说话：频次是证据，"为什么反复出现"是推断，推断要附其他解释，并且不把任何一场的 `no_feedback_inferred` 当作已拒来统计。

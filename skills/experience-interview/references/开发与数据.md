# 开发与数据类经历访谈手册

适用：后端 / 前端 / 全栈 / 算法 / 数据工程 / 测试 / DevOps / 数据分析 / BI / 量化研究。

## 证据载体

| 载体 | 强度 | 说明 |
|---|---|---|
| 代码仓库与提交记录（含作者、时间、PR 评审） | 强 | 能直接证明个人贡献边界 |
| 线上监控 / 性能压测报告（优化前后对比） | 强 | 数字必须带测试条件 |
| 数据看板 / SQL 取数记录 / 分析报告原件 | 强 | 分析岗核心证据 |
| A/B 实验报告（样本量、周期、显著性） | 强 | 没有实验的"提升 X%"按弱证据处理 |
| 技术方案文档、设计评审纪要 | 中 | 证明参与过决策，不证明结果 |
| 线上事故复盘文档（根因、处置、改进） | 中 | 最能证明实战经验 |
| 回测报告 / 策略代码 / 因子库 | 中 | 量化岗；要区分课程与实盘 |
| 竞赛排名页、Kaggle / 天池成绩截图 | 中 | 需附参赛人数 |
| 课程项目报告、答辩 PPT | 弱 | 学生主要素材，需补个人分工 |
| 口头描述、无记录的"我做过" | 弱 | 一律标 pending |

## 评价指标

1. 数据规模：多少条 / 多少张表 / 多长周期 / QPS 或并发量
2. 性能变化：耗时、吞吐、资源占用的前后值，必须说清测试条件
3. 可用性：故障次数、恢复时长、错误率
4. 实验结果：提升幅度 + 口径（次留还是七留、新用户还是全量、分母是否变化）
5. 分析结论是否被采纳：谁采纳、改了什么决策、后续结果
6. 模型指标：准确率 / AUC / RMSE，要写清数据集与线上线下差异
7. 交付范围：独立完成的模块数、负责接口数、覆盖的业务线
8. 自动化产出：报表 / 任务 / 脚本的数量与节省工时
9. 代码质量：测试覆盖率、缺陷逃逸率、评审通过率
10. 量化岗：回测区间、基准、夏普、最大回撤、是否计交易成本

## 术语

- QPS：每秒请求数
- 分库分表：数据库拆分
- 缓存一致性：缓存与库同步
- 消息队列：异步解耦
- 灰度发布：小流量上线
- 回滚：恢复旧版本
- 根因分析：定位事故原因
- 窗口函数：SQL 分组计算
- 次留 / 七留：次日 / 7 日留存
- 漏斗：转化分层
- 归因：剥离外部因素
- A/A 测试：验证分流无偏
- p 值：显著性判断
- 特征工程：构造模型输入
- 线上线下差异：模型效果落差
- 数仓分层：ODS/DWD/DWS
- 调度：定时任务编排
- 数据质量监控：校验脏数据
- 夏普比率：风险调整收益
- 最大回撤：峰值到谷底跌幅
- 未来函数：回测数据穿越
- 覆盖率：测试覆盖比例
- CI/CD：持续集成部署

## 追问清单

**业务背景**
1. 这个系统 / 分析服务什么业务、谁在用、每天大概多少用户或请求？
2. 当时为什么要做这件事：是线上出了问题、业务提了需求，还是你自己发现的？

**规模数据**
3. 处理的数据量级：多少条、多少表、多长周期？
4. 性能或效果数字是多少？优化前后各是多少，在什么条件下测的？

**个人贡献**
5. 你独立写了哪些模块或分析？哪些是协助别人的？
6. 代码仓库或文档里能看到你的署名吗？大概占多少提交？

**成果**
7. 上线或交付后发生了什么：指标动了没有、分析结论被谁采纳、改了什么决定？
8. 有没有被评审、被表扬、被追问的具体记录？

**困难与解决**
9. 卡得最久的问题是什么？你先查了什么，最后怎么定位的？
10. 出过线上事故吗？你做了什么、后来怎么防止再发生？

**关键判断**
11. 技术方案或分析方法当时有哪些备选？为什么选了这个？
12. 有没有你自己拍板、而不是照别人方案执行的决定？

**降级问法**
- 「没做过项目」→ 有没有哪门课的大作业是几人一组写代码、跑数据、做了几周的？课程论文的数据分析也算。
- 「没有线上数据」→ 本地跑过多大的数据集？自己写过定时抓数据、自动出报表的脚本吗？

> 本手册为通用归纳，具体口径以用户实际工作为准

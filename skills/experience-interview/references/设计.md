# 设计类经历访谈手册

适用：UI / UX / 视觉 / 平面 / 交互 / 产品设计 / 用户研究 / 品牌与运营物料设计。

## 证据载体

| 载体 | 强度 | 说明 |
|---|---|---|
| 作品集（含问题、方案演进、最终稿） | 强 | 只有终稿没有过程是弱证据 |
| 设计稿源文件与版本历史（Figma / Sketch） | 强 | 能看出几版方案与个人署名 |
| 上线前后数据（点击率、完成率、投诉率） | 强 | 证明设计被验证 |
| 可用性测试记录、用户访谈纪要 | 中 | 用研核心证据 |
| 设计规范 / 组件库文档 | 中 | 证明体系化能力 |
| 开发交付记录（标注、切图、评审意见） | 中 | 证明协作落地 |
| 竞品 / 体验分析报告 | 中 | 学生可当独立项目 |
| 获奖证书、展览 / 发布记录 | 中 | 需附参赛规模 |
| 课程作业、个人练习稿 | 弱 | 需补是否有真实需求方 |
| 口头"我设计了这个页面" | 弱 | 标 pending |

## 评价指标

1. 方案数量：出了几版、被否了几版、为什么
2. 上线验证：改版前后的转化 / 完成率 / 停留时长，写清指标口径
3. 用户研究规模：样本量、方法、招募方式
4. 交付范围：负责多少页面 / 组件 / 物料、覆盖几个端
5. 规范建设：从零搭建还是沿用、维护了多久
6. 协作效率：评审轮次、返工次数、交付周期
7. 业务结果：活动物料带来的曝光 / 转化（需业务方数据）
8. 无障碍与合规：是否按标准检查过
9. B 端：复杂表单 / 权限 / 流程的处理规模
10. 个人贡献边界：团队作品里你做的具体部分

## 术语

- 用户旅程：使用全流程图
- 信息架构：内容组织结构
- 线框图：低保真布局
- 高保真：接近成品的稿
- 原型：可交互演示
- 可用性测试：真实用户试用
- 设计规范：统一视觉规则
- 组件库：可复用控件
- 标注：给开发的尺寸说明
- 切图：导出素材
- 走查：上线前核对
- 栅格：布局网格
- 响应式：多尺寸适配
- 埋点：数据采集点
- 转化率：目标完成比例
- 热力图：点击分布
- 动效：动态效果
- 品牌 VI：视觉识别系统
- 无障碍：残障可用性
- 设计评审：方案集体审核
- 需求方：提出需求的人

## 追问清单

**业务背景**
1. 这个项目要解决什么问题？需求方是谁、面向哪类用户？
2. 当时产品处在什么阶段：从零设计、改版，还是补物料？

**规模数据**
3. 你负责多少页面 / 组件 / 物料？几个端？
4. 做过用户研究吗？多少样本、什么方法？

**个人贡献**
5. 团队几人？你的环节从哪到哪，交付物是什么？
6. 设计规范是你搭的还是沿用的？

**成果**
7. 上线后有数据吗？看了哪些指标，前后各是多少？
8. 有没有被采纳、获奖、公开发布的记录？

**困难与解决**
9. 开发说实现不了时怎么处理的？最后体验损失了什么、保住了什么？
10. 被否掉的方案有哪些？为什么否？

**关键判断**
11. 出了几版方案？为什么定了这版，依据是数据、用户反馈还是审美？
12. 如果重做，你会改哪里？

**降级问法**
- 「没有商业项目」→ 给社团、比赛、朋友店铺做过海报、公众号头图、PPT 模板吗？有没有人真用了？
- 「只有课程作业」→ 哪份作业有真实需求方或真实用户测试？做了几版？

> 本手册为通用归纳，具体口径以用户实际工作为准

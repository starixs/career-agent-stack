## 1. 定位与取舍

### 1.1 用户与任务（已确认）

- **人群**：中国求职者，以校招应届生为主，兼顾社招；一个求职季同时推进几十到上百条投递。
- **任务**：每天打开就知道最多三件必须做的事；处理新邮件和通知；面试当天一键摊开某家公司的完整档案；复用素材并保持前后说法一致；复盘漏斗。
- **交互模型**：只有一个「个人助理」对话。各个面上的按钮把带对象 id 的意图发进对话。提交和发送永远要经用户批准。
- **设备**：桌面端，主力宽度 1280–1728px，最窄可用 1024px（最窄宽度为暂定）。语言以中文为主，常见中英混排。
- **情绪**：求职期焦虑、被拒频繁、等待时容易反刍。界面要让人觉得可信、平静，不催促。

### 1.2 风格方向：「安静的工作台」

> **视觉方向**（2026-10-09 用户选定）：「手账纸感 + 描边按钮」，温暖、活泼、有人文关怀。逐项细节：主色钢笔蓝、底色象牙白、按钮细描边加小投影、二级栏选中用左侧胶带、中圆角、装饰轻（不铺点阵、所有元素不倾斜）、**不必要的卡片一律去掉**。状态标签第二轮待选（见 6.0）。下表的取舍仍然成立；暖色便利贴、胶带分组标题、文楷标题是「温暖、人文」的主要来源。

| 取舍 | 落到界面上是什么 |
|---|---|
| 内容在前，导航退后 | 一级和二级栏用比内容区更暗一档的底色、更低对比的文字；选中态清楚，但不用大色块 |
| 数据优先，装饰克制 | 不用插画、渐变、玻璃拟态、游戏化徽章；层次靠间距、字重和底色差 |
| 状态可信，不渲染焦虑 | 被拒、沉默用中性灰；红色只留给逾期截止和系统失败 |
| 每个区域一个主动作 | 实心主按钮在一个区域里只出现一次 |
| 人工把关显性化 | 所有要你批准的东西长得一样、出现在同一个位置 |
| 温和而不甜 | 中性色带一点暖调（石色），品牌色用沉稳的靛蓝，不用招聘 App 常见的高饱和橙、青 |

### 2.3 表面与装饰（已确认：装饰轻）

- 不铺点阵、横线；**所有元素都不倾斜**（便利贴、胶带、印章、Logo）。
- 保留的手账元素：便利贴色的用户消息、胶带色块的分组标题（「接下来」「已结束」）、荧光笔划线、文楷标题。
- **去掉不必要的卡片**（已确认）。只有三类东西用卡片：「待你批准」、对话里的工作面工具卡（见 5.7）、文档本身（简历纸）。列表、统计、日程、设置分组、功能入口都直接放在纸面上，用分隔线和间距组织。
- **统计、设置分组、邮箱 / 功能入口、点子、空态一律不画框**（2026-11-05 补）：不写 `rounded-* border bg-[var(--paper)] p-*` 的自制卡，用 `SectionTitle` + `divide-y` 分隔。同一页最多一层卡片；图标不放进描边或淡色方块，直接裸放 20px `--muted`。
- 描边按钮：`1.5px solid --ink` 加 `2px 2px 0 --ink` 硬投影；输入框 `3px 3px 0`；「待你批准」卡 `3px 3px 0`。

## 3. 文字

### 3.1 字体

| 用途 | 字体 | 状态 |
|---|---|---|
| 界面文字与长正文（对话、档案、列表、表单） | 英文 **Source Sans 3**，中文 **苹方 / 微软雅黑** | 已确认（2026-10-09） |
| 标题、小芽说的话、便签等短句 | **霞鹜文楷 Screen**，英文也用它自带的字形 | 已确认（2026-10-09） |
| 简历成品（预览与导出 PDF） | **由简历模板决定，不跟随界面字体** | 已确认（2026-10-09） |
| 代码、日志 | 系统等宽字体 | 暂定 |

```
--font-sans:  "Career Sans", "PingFang SC", "Microsoft YaHei UI", "Microsoft YaHei", sans-serif;
--font-human: "LXGW WenKai Screen", "Kaiti SC", STKaiti, serif;
--font-mono:  "SF Mono", "JetBrains Mono", Consolas, monospace;
```

「Career Sans」是 Source Sans 3 的包装：

```css
@font-face {
  font-family: "Career Sans";
  src: url(./fonts/SourceSans3-Variable.woff2) format("woff2");
  font-weight: 200 900;
  size-adjust: 106%;               /* 原样英文字身比苹方小一号，放大后对齐中文 */
  unicode-range: U+0000-00FF, U+0131, U+0152-0153, U+02C6, U+02DC,
                 U+20AC, U+2122, U+2212;   /* 不含 U+2000-206F */
}
```

- **长正文用普通字体，不用文楷**（已确认）。同一段长回复的 A/B 对比里，文楷的标点前后留白不均、读三四行就累；普通字体扫读明显更快。文楷只用于标题和短句。
- **放大 106%**（暂定）：在 Mac 上与系统字体对照后取的值，中英字身基本对齐。Windows 上还要再看一次。
- **弯引号、破折号、省略号交给中文字体**（暂定）：`unicode-range` 去掉 U+2000-206F 后，中文句子里的「——」能连成一条，引号不再挤。代价是纯英文界面文案里的 “ ” — … 也会用中文字形，目前界面英文很少，可以接受。
- 中文文案用直角引号「」，不用 “ ”。这条也适用于助理生成的内容。
- 字体**全部打包进应用**，不从网络加载：Source Sans 3 约 250KB；霞鹜文楷要按标题和短句的常用字做子集，体积待测。
- 日期、薪资、计数、倒计时、漏斗数字一律加 `font-variant-numeric: tabular-nums`。

### 3.2 字阶（6 档，不允许新增）

| Token | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|
| `--text-xs` | 12 / 18 | 400 · 500 | 时间、计数、徽标、hint、一级栏标签、分组小标题 |
| `--text-sm` | 14 / 22 | 400 · 500 · 600 | **界面默认**：列表行、按钮、二级导航、表单、卡片标题（600） |
| `--text-md` | 16 / 26（对话）· 16 / 28（其他） | 400 · 600 | 阅读型内容：助理对话、开放题答案、面经、审核卡预览、面试模式。对话栏窄于 600px（侧栏打开）时为 15 / 25 |
| `--text-lg` | 18 / 26 | 600 | 页面标题（每页一个）、弹窗标题 |
| `--text-xl` | 22 / 30 | 600 | 今日的问候与首句、档案页公司名 |
| `--text-2xl` | 28 / 36 | 600 | 复盘的大数字 |

- `--text-lg` 及以上的标题、小芽的气泡和便签用 `--font-human`；`--text-md` 的长正文和其他所有界面文字用 `--font-sans`。
- 字重只有 400、500、600 三档。层级先靠字号和颜色区分，再靠字重；不用 700 以上。
- 中文**不用 `uppercase`，不加字距**。小标题就是 12px / 500 / `--muted`。
- 阅读型内容的行宽：对话正文列最宽 820px（每行约 50 个汉字），其他阅读面不超过 40em。
- 对话的阅读节奏（已确认，2026-10-10，见 `chat-density/` 对照）：行高 1.65，段落间距 12，列表项间距 4，嵌套列表 2，列表后 12，三级标题上方 16。只作用于对话（`.chat-reading`），文档与预览沿用默认。
- 对话页去掉顶栏；空输入框收成一行（文字在左、工具在右），打字或加图后恢复两排。
- 发送后的滚动（已确认）：新问题平滑移到视口顶部，回复在下面生成，期间页面不跟随滚动；底部留白只补足「问题到底部不够一屏」的部分，回复长过一屏后留白消失，用户自己往下读。
- 公司名、岗位名单行省略，真实截断并 hover 时显示完整名称；档案页标题允许两行。
- **落地**（2026-11-05）：`src/renderer/index.css` 的 `@theme` 字阶已改成本表的值，行高写 px（`--text-xs` 12/18、`--text-sm` 14/22、`--text-base` 16/26、`--text-lg` 18/26、`--text-xl` 22/30、`--text-2xl` 28/36；`--text-3xl` 与 2xl 同值，只为旧用法保留）。全渲染端生效，包括 keystone 遗留页。`text-[Npx]` 字面量只允许 7.7 的手写大字一处。`--text-md` 在代码里对应 Tailwind 的 `text-base`。

### 3.4 文案规则（已确认，2026-11-05）

页面上只放三类字：
1. **帮他做当前这步**：动作、字段名、状态；
2. **理解当前数据**：值、时间、计数；
3. **决定下一步**：唯一主动作，加至多一条事实句。

不写：
- **页面副标题**：页标题后不跟解释。`CareerPage` 只接 `meta`，放数字事实（「149 个岗位」）。
- **规则说明**：「批准后才会执行」「只存在你电脑上」「红绿灯只是提示」。规则靠控件（禁用、必填、校验）、提交前确认、失败反馈表达。
- **实现细节**：「用授权码」「无需安装扩展」「⌘V」「Shift+回车」。
- **将来式承诺**：「连上后会自动…」。
- **接口名**：`base_monthly` 这类英文键一律经 `structuredLabels` 换中文。
- **空值文字**：空值显示「—」（`EMPTY_VALUE`），不写「未知」「无来源」。

空态 = 一句事实 + 一个动作，不写第二句；按钮直接写动词短语（「研究一家公司」），不包「在对话里说「…」」。字段下不写说明（`Field` 无 `hint`）。
敏感字段：标签前一把锁（`SensitiveMark`，title「只存在你电脑上」），第一次编辑时输入框下出现一次同样的话（`SensitiveFirstEditHint`），不在页面上逐字段重复。
行内次要动作 hover 才出现（`Button reveal`，父行加 `group`），见 7.5。

## 4. 空间、尺寸与表面

### 4.1 间距（4px 网格）

`--space-1` 4 · `--space-1-5` 6 · `--space-2` 8 · `--space-3` 12 · `--space-4` 16 · `--space-5` 20 · `--space-6` 24 · `--space-8` 32 · `--space-10` 40 · `--space-12` 48

| 关系 | 值 |
|---|---|
| 图标与文字、徽标与文字 | 6 |
| 同组元素之间 | 8 |
| 紧凑卡片 / 行的内距 | 12 |

|---|---|---|---|

### 4.3 圆角

已确认「中圆角」（2026-10-09）：`--radius-sm` 4（小色块）· `--radius-md` 8（按钮、导航项、输入框、菜单）· `--radius-lg` 10（三类保留卡片、浏览器侧栏外框）· `--radius-xl` 16（弹窗）· `--radius-full`（头像、对话输入框、分段控件、计数胶囊）

页面里在用的只有三档（2026-11-05 收口）：`rounded-md` 按钮与输入、`rounded-lg` 保留卡、`rounded-full` 胶囊；页面内不用 `rounded-xl / 2xl`（弹窗除外）。

### 4.4 阴影与层次

| Token | Light 值 | 用途 |
|---|---|---|
| `--shadow-sm` | `0 1px 2px rgb(31 29 26 / .06)` | 卡片 hover |
| `--shadow-md` | `0 1px 2px rgb(31 29 26 / .06), 0 4px 12px rgb(31 29 26 / .08)` | 菜单、下拉、Tip |
| `--shadow-lg` | `0 2px 4px rgb(31 29 26 / .06), 0 12px 32px rgb(31 29 26 / .12)` | flyout、对话 Overlay、弹窗 |

- Dark 下阴影透明度 ×2.5，并给浮层加 1px `--line` 描边，因为 dark 下光靠阴影看不出层次。
- 按钮、对话输入框、「待你批准」卡用 2.3 节的硬投影；其余静止元素不加阴影，列表行无边框、无阴影。唯一例外是招聘概览的月历（7.4），它被画成一本实物挂历。
- 柔阴影只用于浮层（菜单、弹窗、浏览器侧栏里的网页外框）。

### 4.5 层级（z-index）

内容 0 · 粘性页头 10 · 二级栏 flyout 30 · 对话 Overlay 40 · 菜单与下拉 50 · 弹窗 60 · Toast 70 · Tip 80

### 5.3.1 浏览器现场与私密信息的去处（已确认，2026-10-09）

- **浏览器现场不再有独立页面**，是对话页的一个工具和侧栏（已确认，交互参照用户给的 Muse 截图）。分三种状态，样稿见 `shell-browser-card / -open / -handoff.png`：

### 5.7 对话内工作面：收起 / 展开 / 交接（已确认，2026-10-09）

对话里凡是有「工作面」的功能，都用同一套三态，交互流程保持一致。浏览器现场（5.3.1）是第一个，其他功能照抄：

| 功能 | 工作面里是什么 | 典型的交接点 |
|---|---|---|
| 浏览器（填网申、找岗位） | 实时网页 | 登录、验证码、最终提交 |
| 改简历 | 简历成品预览，带修改前后对比 | 采纳哪几处修改 |
| 开放题、招呼语草稿 | 草稿和所用素材 | 批准发出 |
| 模拟面试 | 题目、计时、你的作答和逐题点评 | 轮到你回答 |
| 笔试练习 | 题目与作答区 | 轮到你作答 |

三态的统一规则：

1. **收起**：对话流里一张「打破式」卡片（已确认，2026-10-13，实现在 `features/career-shell/BreakoutCard.tsx`）。平时**没有外框、底色和投影**，直接排在对话背景上；hover 时纸面轻微抬起、阴影加深，右下的「打开 XX」变成描边小投影按钮（文案按功能写，如「打开浏览器」「打开简历」），点卡片任意处都能打开。所有工作面共用一套语法，排版按对象换：
   - 左边**只有一个视觉锚**：简历是文档页缩略，定制简历是「N 处修改」大数字，模拟面试是「开场 / 追问 / 复盘」竖排轨道，笔试是「已答 / 总数」加进度格，浏览器是实时缩略。
   - 右边五层字：文楷主名称 + 灰色旁注、宽字距的次级标注、一段正文（一条前后对比、一道题）、细线加键值行。
   - 状态只放在右上角的小角标里，颜色同下文状态点。
   - 内容由 tool 返回的字段驱动，缺哪个字段就收起哪一行；私密库占位符（`{{vault:…}}`）不在对话里显示。
   小芽面板的状态行和「正在做」同步显示同一件事。
   卡片字段表见 §5.7.1。
2. **展开**：工作面在对话页右侧变成宽侧栏，替换小芽面板；对话收窄到左边约 460px；小芽缩成对话区左上角的浮动头像，带一句状态。侧栏顶部固定为「名称、状态点加对象」，右边依次是「停止」、主动作、关闭。工具卡上的按钮变成弱化的「已在右侧打开 →」。
3. **交接**：轮到用户的时候，状态点由绿变黄，侧栏顶部出现一条提示「这一步要你本人来」，说明要做什么；主动作变成「交还给小芽」或「批准 / 采纳」。对话里同步说明停在哪一步。
4. **结束**：工具卡留在对话里，状态变成「已完成 · 查看」，点了仍可在侧栏里回看。

通用约束：

- 同一时间只展开一个工作面；打开另一个时，前一个自动收起成工具卡。
- 关掉侧栏不停止工作，只有「停止」才停。
- 「待你批准」卡就是提交类动作在收起态下的交接；展开后就是该工作面的交接态，按钮和文案保持一致。
- 状态点：绿 = 小芽在做，黄 = 等你，灰 = 已结束，红 = 出错（附「重试」）。

## 6. 状态语言

### 6.0 状态标签的样子（已确认：左侧色条，2026-10-09）

状态写成「3px 状态色竖条 + 8px 间距 + 13px / 500 状态色文字」，不铺底、不加框、不倾斜，单行不换行。见 `tuning/var-5-round2.png` 的 C。下面 6.1–6.3 的「徽标」都指这个样子，颜色语义不变。

### 6.1 投递阶段

投递线里的阶段用**分组**表达，行内徽标只出现在跨分组的视图（通知收件箱、全部、搜索结果）。

| 阶段 | 徽标 | 说明 |
|---|---|---|
| 待投 | 中性 | |
| 已投 | 中性 | 是常态，不需要吸引注意 |
| 有回应 | info | 有进展 |
| 笔试 / 测评 / 面试 | 钢笔蓝（`--primary`） | 当前最需要投入精力 |
| Offer / 已入职 | success | |
| 需要你 / 卡住 | warning，文字写「需要你」 | 要用户动手 |
| 被拒 | 中性，文字用 `--muted` | **不用红色**，被拒是求职常态，不是错误 |
| 沉默 | 中性，写「沉默 N 天」 | 给事实，不给警告色 |
| 放弃 | 中性，整行文字降为 `--subtle` | |

中性状态：`--muted` 色。

### 6.2 截止紧迫度

适用于测评、笔试、面试、三方、内推码有效期：

| 剩余时间 | 呈现 |
|---|---|
| > 72 小时 | `--muted` 文字「10 月 12 日截止」 |
| 24–72 小时 | warning 徽标「剩 2 天」 |
| < 24 小时 | danger 徽标「剩 5 小时」，自动进入工作台「今天的三件事」 |
| 已逾期 | danger 文字「已逾期 3 小时」，带处理动作（标记已完成 / 交给助理） |

倒计时写绝对剩余量，不只写「即将截止」。

### 6.3 内容可信度

| 状态 | 呈现 |
|---|---|
| 助理生成、用户还没确认的经历或主张 | 左侧 2px `--line-2` 虚线，加中性徽标「待确认」 |
| 用户已确认 | 正常样式，不加标记 |
| 用过的素材 | `--text-xs` / `--muted`「对 字节、美团 说过」，点击展开使用记录 |
| 前后说法不一致 | warning 徽标「说法不一致」，加对比入口 |

### 6.4 通用交互状态

| 状态 | 规则 |
|---|---|
| hover | 只换底色，不位移，不改变布局 |
| focus | 键盘焦点必须显示 2px `--primary` 焦点环；hover 才出现的动作在 focus-within 时也要出现 |
| 选中 | 底色加指示线，不能只靠颜色区分 |
| 禁用 | 文字 `--subtle`，必要时在旁边说明原因；不用 50% 整体透明 |
| 加载 | 同尺寸骨架或原位转圈，容器尺寸不跳 |
| 空态 | 说明下一步，并给一个「交给助理」按钮；空态和「加载中」不能长一样 |
| 错误 | 局部出错只在局部显示并给「重试」，保留用户已输入的内容 |
| 成功 | 结果已经在原位出现时不弹 Toast |

## 7. 组件规则

### 7.1 按钮

| 变体 | 外观 | 用途 |
|---|---|---|
| Primary | `--primary` 底、白字、1.5px `--ink` 描边、2px 硬投影 | 区域内唯一主动作：「批准并发送」「开始投递」 |
| Secondary | `--paper` 底、1.5px `--ink` 描边、2px 硬投影 | 并列动作；**「交给助理」默认用这个** |
| Ghost | 透明底、`--muted` 字，hover 时出底色 | 行内与工具栏动作 |
| Danger | `--danger` 文字，不铺底色 | 只用于删除数据、撤回已发出的内容 |

### 7.2 审核卡（待你批准）

submit / send_greeting / answer_open_q 统一使用这张卡：

#### 7.3.2 笔试助力（搜题）

- 定位：现场答题时截图或粘贴题目，马上拿到答案；原来的「出题 → 作答 → 批改」（笔试练习）以后归题库刷题，不在这里。前提见 `CAREER_WORLD.md`「题」「搜题要的效果」与立场 8。
- 入口：功能市场「笔试助力」直接打开；助力记录里笔试、测评行的「助力」带着公司和岗位打开。页面挂在 `career-dossier` 的 `exam-search` 视图，打开时 L1 停在功能市场。
- 单位是**一场笔试**（2026-11-05 收敛）：每次粘贴是这场里的一步。第一次粘贴开一场；「新的一场」清空重来；打开页面时最近一场 3 小时内动过就接着它，否则从空白开始。
- 顶部「这场笔试」：公司、岗位两个输入框，默认取最近一场笔试或测评（几小时前开考的也算），旁边列出最近几场可一键切换；改了就记到这场上。
- 主体三栏：**左栏**是粘进来的题，**中间**是前后箭头和「第几 / 共几」（键盘 ← → 同样能翻），**右栏**是答案。整页监听粘贴（Mac ⌘V / Windows Ctrl+V，提示按系统显示），文字、截图都是粘进来就搜；也可拖图进左栏。截图长边缩到 2000 像素再传。
- **宠物截图**（2026-11-05）：「开始这场」把这场设为正在考（`exam_session.live_at`，同时最多一场；宠物没开就顺手打开）。开考期间点宠物不再唤出对话，而是调系统框选截图（macOS `screencapture -i`；Windows 系统截图 `ms-screenclip:`，框完从剪贴板读、PowerShell + System.Drawing 转 JPEG；Esc 取消，Windows 上靠框选界面关闭且剪贴板没变判断取消），截图挂在宠物身上（角标 = 张数，最多 6 张），宠物小面板换成「缩略图托盘 + 发出去 + 这场的答案（左右翻）」，主窗口也显示同一个托盘、也能发。**几张一次发**：按顺序一起认题，被截成两半的题、材料和题目分在两屏的都能拼上。截图只在侧车内存里，发出即清空；「结束这场」恢复宠物原来的点击行为。主窗口、宠物、小面板之间靠侧车广播和 `fb:exam-changed` 互相提醒重新取。
- 左栏不放原图：认完题后按模型抄下的**共用材料**（阅读段落、资料分析表格，Markdown）、题号、题型、题干、选项统一排版，截图和文字看起来一样，题号和右栏对齐；还在认题时先淡显粘进来的原样。记录里只存这份文字（`exam_search.material` + `questions_json`），不存截图。
- 流程分两步：识别（模型拆题、抄材料 + 题库检索，原题当场给答案）→ 作答（其余题带材料和参考题交给模型）。几次粘贴可以同时在路上，各自回填自己那一步。
- 检索：题库 = 我们整理的 + 用户上传的。按题干 trigram 召回、二元字相似度精排，分级加分「同公司同岗位 → 同岗位别家 → 同公司别的岗位 → 通用」。原题要求字面足够像且数字一致（改了数字答案就变了）。
- 右栏一题一行：答案大字先行（性格题叫「建议倾向」）；出处只标题库给的：题库原题（带公司 · 岗位 · 年份）/ 参考了某级类似题，模型自己答的不挂出处；拿不准标「拿不准」。解析、类似题默认收起。
- 「记录」页签：按场列出（公司 · 岗位，没填就用第一道题；时间、粘了几次、几道题），点开回到那场的最后一步，可以接着粘；可整场删除。只是自己的记录，不回流题库。
- 题库的上传和管理先隐去（后端检索和上传接口保留，`BankManager` 暂不挂载）：上传 PDF、Word、Excel、图片、文本或 JSON，可填公司、岗位、年份；后台拆题（没给答案就留空，不编）；我们整理的题库不可删。

- **招聘概览** = 左边整月月历（上个月 / 今天 / 下个月）+ 右边选中那天的待办（默认今天）。替换了原来的「最多三件事」卡片、起步清单和「等待中」。

  - 以后的待办通过页面底部输入框跟小芽说（deadline_add）；输入框位置先留空（`data-slot="page-ask-bar"`，约 96px）。

### 7.4.1 我的资料 · 简历（已确认：汇总页 + 编辑页，2026-10-10）

### 7.4.2 功能市场（2026-11-05 改：按内置技能摆，10-13 版作废）

功能市场的作用是把小芽会的本事摆出来。清单只有一份（`components/career/skills/catalog.ts`），和内置技能（`app/skills/`）一一对应，有测试守着：新加一个技能必须在这里给它一个位置。**没有「添加 / 安装」按钮**，点了直接用。

功能市场是橱窗：给人看我们有什么，不是给着急的人找工具。所以清楚、好认、调性一致最要紧。

- **卡片 = 一幅插画 + 名字。** 插画画的是一眼认得出的东西（对话气泡、答题纸和笔、信封、路牌……），画法跟产品的笔触走：墨线描边、便签黄 / 薄荷 / 钢笔蓝这些主题色块、主体带一道硬投影（`SkillArt.tsx`）。不放文字，也不画只有粗细线条的抽象示意。这一页用卡片是 2.3「去掉不必要的卡片」的例外。
- **页面上不写说明性的句子。** 没有副标题、没有功能介绍、没有「点子」区。工作台卡只有插画和名字，**不放计数**（「6 条预测 · 2 场模拟」这类数新用户看不懂、老用户用不上）；技能点卡多一行它交回来的是什么，十四个字以内。
- 分两种形态：
  - **工作台**：能独立成事的技能，一张大卡，点了去它那一页。面试助力、笔试助力（7.3.2）、简历、网申进展、公司调研、Offer 对比、我的求职月。
  - **交给小芽（技能点）**：聊天过程中会触发的特化能力，两列小卡。有东西要选或有成果可看的，点开原地换成详情（左上角返回）：插画、名字、「选一下点一下」的开始条，下面是它做出过的成果；自己在做的（回音归类）点了去看结果；其余的点了把那句话预填进对话输入框（`mode: 'prefill'`）。 用不上的不上市场（校招节奏，2026-11-05），技能本身照常可被调用。
- **一键开始**：技能要的东西（岗位、公司、题目类型）做成选择，他投过的直接列出来，选好点一下就发进对话，对象 id 走隐藏上下文（`mode: 'send'`），不用打字。
- 从工作台或技能点详情发出去的话，回复结束后对话里有一张卡带他回到这一页看成果（`pageSurfaceId`）。

### 7.4.2a 工作台页：用图形把功能做出来，不用文字堆（2026-11-05）

做一页之前先写一句「他在这页要看见什么」，再决定用什么图形把它做出来；文字只做标签和内容本身。共用的部件在 `components/career/skills/visual.tsx`：

| 要表达的 | 用什么 | 例 |
|---|---|---|
| 几类各有多少 | 分段条 + 带数的图例 | 预测追问的高 / 中 / 低风险；题目练没练过 |
| 有几件、各是什么状态 | 点阵：一件一颗，颜色是状态，空的是虚线（`Marks`） | 步骤块上的预测（按风险上色）、题目（练没练、过没过）、要补的事（空方框） |
| 会被追多深 | 深度格：像信号格，一层一格（`DepthBars`） | 预测列表里每句话右边 |
| 追到第几层卡住 | 追问轨道：一层一站，走过的实心，卡住的是红叉，没到的虚线（`DepthTrack`） | 模拟报告和复盘的追问卡 |
| 一层比一层深 | 逐级往里缩的阶梯，带圈数字 + 气泡，最深一级描风险色 | 预测的追问链 |
| 别人怎么想 | 带人像的气泡；「也可能是」是虚线气泡 | 面试官的看法、现场信号的另一种解释 |
| 推测出来的、还没核实的 | 虚线：虚线框的章、虚线气泡；要先核实的事是空方框 | 推测的面试结果、便签里的「先核实」 |
| 一个结论 | 印章（描边 + 同色字） | 很值得投、有点悬、进入下一轮、黄灯 |
| 一个量 | 内嵌底色的大数字块 | 红线命中 / 没查到记录 / 没法确认 |
| 哪天、还有几天 | 日期块；从今天伸到期限的条 | 面试票上的日期；Offer 的答复期限 |
| 谁多谁少 | 同一把尺子的并排条，下面小字写怎么算的 | Offer 一年的钱 |
| 几个方面各多少分 | 雷达图，旁边是分数和依据 | 岗位评估的五项 |
| 亮什么灯 | 三盏并排的灯 | 公司调研的红黄绿 |
| 一句要带走的话 | 便签（便签黄底） | 面试时怎么问、这道题可以怎么答 |
| 要去做的事 | 前面一个空方框的待办 | 回去要补的、投之前要确认的、要你自己核实的 |
| 一条路上的第几步 | 带编号的数字块页签 | 面试准备的 ① ② ③ |
| 一道题练得怎样 | 分数环（没练过是虚线空圈，不到过关线用提醒色） | 准备页的题、题库 |
| 几个并列的选项各自怎样 | 并排的卡，选中的描墨线带硬投影 | 方向探索的路牌 |

**先换位，再分两层。** 每个工作台动手前先回答三个问题：他什么时候会点开这页、那一刻最想知道什么、看完要做什么。然后把页面分成两层（部件在 `components/career/skills/layers.tsx`）：

- **第一层 · 宏观**：一句结论、两三个要点（`PointRow`，带圈数字 + 一句话），或者一个图形量。一眼知道总的情况和最要紧的事。这里的「打分」不必是分数。
- **第二层 · 分项**：一排数字块当页签（`TileTabs`），每块是一个分项和它的量；点哪块，下面摊开哪一项，**一次只看一项**。页面不是从上到下一长串。
- **文字只承担要读的内容**：面试官会问的那句话、简历里被追问的那句话、可以怎么答、公司是做什么的。其余（状态、数量、深浅、先后、谁多谁少）都用图形和结构。
- 同一件事的问题和答案放在一起，不分成上下两段让人对。
- **不用带小竖杠的标签，相邻的一小块里不同时出现三种字号。** 一页要么是「看」的状态，要么是「做」的状态；做的事由系统安排（比如练题由小芽发题），不让人一条条挑。
- **一个状态只说一次，用颜色或形状说。** 左边已经有一道风险色，就不再写「高风险」三个字，也不再配一条图例；块上已经是点阵，面板里就不再放一根比例条。小标题能靠形状认出来的（便签、待办方框、带色标签）就不挂小标题。
- **数字块上优先放图形而不是数字。** 「3」得读旁边的小字才知道是什么；六颗按风险上色的方块不用读。
- 长列表先想能不能做成左右两栏：左边是短的条目，右边是选中那条的细节，一次只看一条。

### 7.4.3 我的资料 · 基本资料（已确认，2026-10-13）

- 第一眼要干净：只让用户填**身份**（姓名、性别、出生日期、身份证号，两列）和**联系方式**（手机号、邮箱、微信号）。教育、求职偏好、民族、政治面貌不在页面上，私密库里仍有字段，网申用到时由小芽问了再存。
- 下面是**绑定账号**：邮箱同步、领英、脉脉、GitHub、个人网站、学信网。绑定时只填主页或用户名（学信网只授权），然后交给小芽抓一次；需要登录的站点由小芽打开，登录交给本人。
- 绑一次抓一次，不天天爬。小芽抓完用 `account_fetch_report` 回报，行内显示「已交给小芽 / 上次抓取 N 天前 / 上次没抓到：原因」；登录过期时徽标变 warning、写明「登录已过期」，按钮变成「重新绑定」。
- 小红书、抖音等社交账号待合规调研后再加。网申答案、投递网站登录、经历的保密补充收进底部默认收起的「更多」。

### 7.5 列表行

- 单行 40px：左边公司名（`--text-sm` / 500）、岗位（`--ink-2`），右边元信息（截止、阶段徽标、时间）右对齐。
- hover 时行末浮出 Ghost 操作按钮，**覆盖在元信息上方**，不挤压标题宽度。
- 整行可点击并可用键盘 Enter 打开；行内按钮阻止事件冒泡。

### 7.6 浮层

- 菜单、下拉：`--radius-lg`、`--shadow-md`、内距 4、每项 32 高。危险项放末尾，用分隔线隔开。
- 弹窗：`--radius-2xl`、`--shadow-lg`、宽 480 / 640 两档，Esc 关闭，关闭后焦点回到触发入口。
- Toast：右下角，最多同时 3 条，4 秒消失；有动作的 Toast 停留 8 秒。

### 7.7 手写语句（已确认，2026-10-28）

- 内置鸡汤与诗文两类短句（`components/career/handwriting/quotes.json`），按场景出现：招聘概览「今天」栏底部（还有事 / 都划掉了 / 没有待办）、求职漏斗有被拒或沉默时、投递记录与漏斗为空时。同一天同一场景固定一句。
- 直接写在界面原有底色上，不另加纸面。字形用书法手迹字体**志莽行书**（SIL OFL 1.1，`glyphs.json`），保留原字的大小错落、原字重、不洇墨；墨色 `--hw-ink`（墨绿，深浅两套）；`--text-xl`。
- 运笔从字形反推：楷体笔顺中轴（hanzi-writer-data，`strokes.json`）拉伸对齐到字形，每个墨点归到最近的一笔、按笔内位置出墨。逐组比较后定版的动画参数：每笔起收强度 0.55；墨从中轴晕开 1 毫秒/像素；字间停 70 毫秒、标点停 600 毫秒（原速计）；整句先按原速慢写 2 秒，再用 0.6 秒平滑加速，6 秒写完。只在逗号句号后换行。
- 漏斗页语料（2026-10-28 用户审定，52 句）：按求职状态分五组——起步（还没投）/ 等待（投出未回音）/ 受挫（被拒与沉默占多数）/ 推进（有笔试面试）/ 收获（拿到 offer），场景名 `funnel-*`。约一半取自用户提供的社群「接龙」金句（可拆句、尽量不改写），一半是古诗；每句不超过 14 个字（含标点），保证 App 里一行放下。每次打开漏斗页从对应那组随机挑一句，不与本机上一次显示的重复（`QuoteNote pick="random"`）。
- 漏斗页（我的求职月）的位置：放在顶部数字行里，四个大数字和「用我们以来 · 替你投出」之间的留白处，靠右、垂直居中（2026-10-28 用户改定；原先放在整月最底部做落款）。这个月还没投出时，漏斗摆标准初始形状，不再单独做空状态页，手写照样按「起步」组选句。字号是**展示型字号 30px**（字阶外）：和 56px 的大数字同在一行，要压得住又不抢。代码里对这一行单独放行并注明本节。
- 漏斗页整体尺寸按 24 寸屏一屏放下整月来定：大数字 56px、漏斗高约 330px、每一天的柱高 120px（2026-10-28）。
- 每次打开应用每句只写一遍，不循环；`prefers-reduced-motion` 下直接显示终态；不支持 canvas 时退回文楷文字。改了语句后跑 `node scripts/build-handwriting-strokes.mjs` 和 `python3 scripts/build-handwriting-glyphs.py`。
- 手迹本身带书法的倾斜与大小错落，是本组件的特例（1.2「所有元素不倾斜」不适用于字迹本身）。

## 9. 落地与维护源

### 9.1 Token 与主题（已确认：删除 keystone 的界面 Token，2026-10-09）

keystone 的界面类 Token 和主题体系**全部删除**，只保留本文定义的一套（浅色 + 深色）。现状规模（2026-10-09 统计 `src/renderer`）：约 340 个文件引用 keystone Token，最常用的是 `--ink-muted`（约 2000 处）、`--ink`、`--line`、`--paper-inset`、`--accent`、`--paper-elevated`；`theme/themes/` 下有 9 套主题，另有 `registry.ts`、`ThemeRuntime` 和一组主题测试。

做法：

1. **新建唯一的 Token 文件**（如 `src/renderer/styles/tokens.css`），定义第 2–4 节的全部变量，浅色写在 `:root`，深色写在 `[data-theme="dark"]`，再用 Tailwind v4 的 `@theme` 暴露成 utility。业务组件不写 `[var(--…)]` 任意值、不写 `text-[Npx]`。
2. **同名直接接管**：`--ink`、`--paper`、`--line`、`--success`、`--warning`、`--info` 这类与新方案同名的变量直接换成新值。
3. **旧名一次性改写成新名**，用脚本批量替换，不留别名：

| keystone 旧名 | 新名 |
|---|---|
| `--ink-muted` | `--muted` |
| `--ink-secondary` | `--ink-2` |
| `--ink-subtle`、`--ink-faint` | `--subtle` |
| `--paper-elevated` | `--paper` |
| `--paper-inset` | `--inset` |
| `--line-subtle` | `--line` |
| `--line-strong` | `--line-2` |
| `--hover-bg` | `--hover` |
| `--accent`、`--focus-border`、`--button-primary-bg` | `--primary` |
| `--on-accent`、`--button-primary-text` | `--on-primary`（白） |
| `--error`、`--error-bg` | `--danger`（不铺浅底） |
| `--accent-warm*`、`--global-sidebar-bg` 等主题专属名 | 按用途映射到 `--side`、`--rail`、`--note` 等，逐个确认 |

4. **删除**：`theme/themes/` 下 8 套可选主题、`preset-theme` 生成器和设置里的主题选择器；设置只保留三种外观模式。`specs/DESIGN.md` 与 `tech_docs/theme_system.md` 不适用于本产品。
5. **范围注意**：这一步动到了 keystone 的非求职页面（Task Center、Records、设置等），它们的颜色跟着变成新配色，布局不变。

**落地情况（2026-10-09，分支 `feat/career-design-tokens`）**：

- 唯一的主题包是 `src/renderer/theme/themes/career.css` + `career.ts`，前者是第 2–4 节数值的运行时来源；`registry-contract.ts` 只要求本文的 Token。
- 主题 ID 仍是 `keystone-default`，这样用户已存的配置不需要迁移；默认主题和兜底主题都是它。
- 主题运行时（`ThemeRuntime`、`registry`）保留，因为代码编辑器、终端、Mermaid 图、代码高亮和 Widget iframe 都通过它拿配色；它现在只注册这一个主题。
- 旧名到新名用 `scripts/design/rename-tokens.py` 一次性改写；`themeArchitecture.test.ts` 里有一条守卫，渲染端源码再出现旧名就会失败。
- 字体打包在 `src/renderer/assets/fonts/`，由 `theme/fonts.css` 声明：Source Sans 3 拉丁子集（28KB）和按字符区段切成 97 份的霞鹜文楷（共 5MB，只加载屏幕上用到的分片）。
- 深色配色是暂定值，等深色专项再校准。

外观只有三种模式：**浅色 / 深色 / 跟随系统**，只有这一套配色，不提供主题目录（**已确认**，2026-10-08）。设置里的外观选项是三选一，默认「跟随系统」；keystone 原有的 9 套主题不随求职产品发布。

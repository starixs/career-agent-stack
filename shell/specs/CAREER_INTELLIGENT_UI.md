## 1. 为什么要改

1. **长任务把人看丢。** AI 连着做很多事，用户脑子里「到哪了、哪些要我管」会越来越模糊，只能往上翻或者再问一遍。
2. **同一个人对不同岗位想管的程度不同。** 对目标公司想逐份过目，对海投只想知道结果。
3. **用户是 00 后。** 习惯短、即时、图像化的信息。只借鉴节奏，产品是电脑端，尺寸和素材按桌面来。

参考：OpenAI 2026-10-07 发布的 Intelligent UI（回答由受信任的原生组件拼成、文字更清楚时就用文字）；Horvitz 的混合主导原则（有把握就做，猜错代价要低，随时能纠正）。

## 2. 设计前提（已确认，2026-10-27）

跨功能的前提以 `specs/CAREER_WORLD.md` 为准，这里只列和本切面直接相关的部分。上一版（方案三）用「交叉、并行、长程」三种情况压测后失效，挖出的隐性假设改成下面这些前提：

| 维度 | 前提 |
|---|---|
| 任务单位 | 是**一份申请（一个岗位）**，跨数周到数月；一次流程只是其中一段。数据层本来就按申请建模（`application`、`application_history`、`deadline`、`action_queue`、`inbox_item`、`handoff`） |
| 驱动来源 | 多数后续由**外部邮件**触发（笔试、面试、拒信），量大；没回音也是一种状态。外部输入**只收邮箱**，不收短信 |
| 共用资料 | 主简历、资料库、常见问答被几百份申请共用，改一处影响一批 |
| 重要程度 | 差异很大：少数目标公司深做，大部分海投 |
| 注意力 | 用户不盯着 AI 干活。准备期几周来一次，关键期每天来；回来最想知道「现在有什么在等我」 |
| 紧急度 | 由外部期限（截止、笔试、面试时间）决定，不由 AI 进度或用户何时打开决定 |
| 后悔与撤回 | 后悔常在几小时到几天后、以一批为单位；提交后就撤不回，可撤回性随时间变化 |
| 人群 | 「省心 / 协作 / 掌控」不是固定人群，同一个人对不同岗位、不同阶段会变 |

背景事实：应届生秋招、春招，整个求职约一年；关键期连续几个月每天投十几到几十家，总计二三百份。

## 3. 一条规则

**AI 在后台干活；对话里只出现「要你的事」和你回来时的简报。同一件事是同一个对象，可以出现在多处（对话、等你条、各页面），在哪一处处理都算处理，处处一起更新。要你的事在对话里的落点是输入框上沿的等你条，按外部期限排序。**（已确认：2026-10-27 选定「做法三」；2026-10-30 改写，不再追求「只有一个落点」）

- 一个对象多处：起步卡与招聘概览上的起步块、接管卡与接管简报页、等你条里的事与月历上的同一件事，都是同一个对象。处理一处，其他地方同时消失或更新，不各自留一份状态。
- 不要你的事只进数字（「投出 10 / 17」「其余 13 家还没回音」），不逐条推。
- 管多少按岗位调：标了星的目标岗位投前先给你看；海投只在缺信息、要登录、有外部期限时出现。
- 对话仍然是唯一入口，不另开会话或表格。

被否决的做法（记录在案，避免反复）：

| 做法 | 否决原因 |
|---|---|
| 自主度旋钮（开始时选全托 / 协作 / 我来） | 要先判断自己是哪种人；同一个人对不同岗位偏好不同；本质是三套界面 |
| 按行为自动收放（系统悄悄猜） | 界面自己变，用户说不清为什么；猜错时是隐形的 |
| 方案三：先做 + 撤回，回执胶片 + 进度条 + 5 秒撤回 + ⌘Z + 侧栏 | 默认「一条线性流程、用户一直盯着、几分钟内后悔」。交叉时两条胶片缠在一起；并行时 20 条进度条刷屏；长程时撤回提示早已消失、提交后根本撤不回。组件和样式一律不复用 |
| 做法一：一家一个会话 | 二三百家就是二三百个会话；改共用资料要逐个会话通知；回来时不知道先看哪个 |
| 做法二：对话里放一张总表 | 把「整体局面」塞进对话，和其他页面重复；表格只能看状态，看不出哪件急 |

## 4. 术语

| 术语 | 含义 |
|---|---|
| 要你的事 | 只有你能做、AI 停下等你的事。五类：缺信息、要登录、有期限、选时间、投前过目 |
| 等你条 | 固定在输入框上沿的一行：「等你 N」+ 最多 3 个公司小签 + 最早的期限；右边是本批「投出 x / y」 |
| 卡组 | 点等你条后在它上方展开的浮层，一次一张要你的事 |
| 批次卡 | 一次「这些都帮我投」在对话里留下的一张图：目标岗位大海报 + 其余小海报 |
| 回来卡 | 离开超过半天后回来，对话里出现的简报 |
| 更正卡 | 改了被一批申请共用的东西后出现：哪些换成新版、哪些已投出改不了 |
| 申请对象卡 | 问「某家怎样了」时出现，一家一条从投出到下一步的路 |
| 公司海报 | 一份申请的图形，四档大小，见 6.2 |
| 起步卡 | 第一次打开、还没连邮箱也没有任何申请时，对话里请用户把手里有的给我：连邮箱、拖简历、说一件做过的事 |
| 接管卡 | 第一次连上邮箱、历史邮件收完后，对话里的一张简报：替你接管了几家、最急的一件、几行事实 |
| 接管简报 | 接管卡的完整版，一个单独的页面 |

## 5. UX 规则

### 5.1 对话里出现什么

只有这些：

1. 用户的话和 AI 的简短回复（文字是默认；解释、建议、闲聊都用文字）。
2. 批次卡、回来卡、更正卡。
3. 问到某一家时的申请对象卡。
4. 单独展示一个对象时的打破式对象卡（如「看看我的主简历」，已确认，沿用 `cards.tsx`）。
5. 冷启动：第一次打开时的起步卡；第一次连上邮箱、历史邮件收完后的接管卡（见 5.11）。

AI 的过程步骤（定制、填表、上传）不进对话。回复文字不重复卡片里已有的内容。

### 5.2 等你条与卡组

1. **一个落点**：所有要你的事只进等你条，不在对话流里插卡，不随对话滚走。
2. **排序**：按外部期限，越急越前；没有外部期限的（缺信息、要登录）按它挡住了多少份申请排在有期限的之后。**例外**（已确认，2026-10-30）：邮箱连接失效排在最前。它没有外部期限，但挡住的是之后所有邮件，不处理就会漏掉期限。
3. **合并**：只在「一个动作能同时解决」时合并。例：20 家都要证件号码，算一件；两个网站要登录，一次登录之旅算一件。不按类型合并。
4. **打开方式**：点等你条打开卡组，←→ 切换，Esc 收起。卡组只在一种情况下自己弹出：这件事是用户刚说的话直接引起的，且用户没有在输入。
5. **卡组里的位置要稳**：新事进来重排后，仍停在用户正在看的那张上。
6. 等你条为空时只显示「投出 x / y」或什么都不显示。

### 5.3 要你的事（五类）

| 类 | 图 | 动作（≤ 2 个） |
|---|---|---|
| 缺信息 | 涉及的公司小签铺成一片 | 就地填（敏感项密码式输入）· 「这批先跳过」；认不出名字的格子不进卡，只给「去看」 |
| 要登录（含邮箱连接失效） | 两张中海报；邮箱失效时是邮箱图标 + 「新邮件暂时收不进来」 | 「去登录」/「重新授权」· 「晚点」 |
| 有期限（笔试、测评） | 一张大海报 + 期限大字 | 「去做测评」· 「提前 1 小时提醒我」 |
| 选时间（面试） | 一张大海报 + 3 个时间 | 「确认这个时间」· 「都不行」 |
| 投前过目（目标岗位） | 公司大海报 | 「投出」· 「去看」（画面切到这一家填好的页面）（2026-11-05 用户定） |

每张卡悬停时出一行安静的选项：投前过目是「这家以后不用先给我看」，其余是「这类以后别问我」。

### 5.4 管多少按岗位调

- 标星的目标岗位：投前过目。
- 批次卡里悬停任一家出「这家我要看」，点了这家就改为投前过目。
- 「这类以后别问我」「这家以后不用先给我看」当场生效、跨会话持久。查看和撤回这些规则的地方见第 11 节未决项。

### 5.5 批次卡

- 标题「投 20 家」+ 一行数字「10 已投出 · 2 在投 · 3 等你」（等你为钢笔蓝）。
- 目标岗位用中海报，海报底部写状态字（排队 / 定制中 / 等你看 / 已投出）；其余用小海报。
- 只反映状态，不放动作；动作都在等你条。

### 5.6 回来卡

- 离开超过半天才出现。
- 最急的一件放最大：大海报 + 事由 + 期限大字 + 「从最急的开始」（打开卡组并定位到这件）+ 「还有 N 件等你」。
- 下面几行事实：数字 + 类别 + 公司小签，例如「17 已投出」「1 面试邀请」「2 笔试 / 测评」「2 不合适」，末尾一句「其余 13 家还没回音。」
- 拒信只计数，不单独推。
- 准备期没有要你的事时，只写事实（如「暑期 5 家没回音」「提前批 字节 10 月 13 日开」）。
- **历史导入不算「离开期间发生的事」**（已确认，2026-10-30）：第一次连邮箱后用接管卡（5.11）代替回来卡；之后的回来卡只算接管之后的新事，不把旧账再报一遍。

### 5.7 更正卡

- 改了共用资料（如简历项目名错字）后出现。
- 两堆：「N 家换成新版」（换版中的小签）和「N 家已投出，改不了」（整体变淡）。
- 不做撤回：已投出的就是改不了，明说。不写改了什么，悬停小签看那家用的是哪版。

### 5.8 申请对象卡

- 问「京东那份怎样了」时出现。左边公司大海报，右边一条横向的路：投出 → 面试邀请 → 确认一面时间 → 一面。
- 发生过的节点为墨色，等你的那一节为钢笔蓝，没到的为灰。动作悬停出现。

### 5.9 系统通知

- 软件关着时，只给带外部期限的事发：前一天晚上一次、当天上午一次。
- 拒信、没回音、投出都不发。

### 5.10 键盘与无障碍

- 等你条可聚焦，Enter 打开卡组；卡组 ←→ 切换、Esc 收起，收起后焦点回到等你条。
- 悬停才出现的动作在键盘聚焦时同样出现。
- 新的要你的事进入等你条时，通过 `aria-live="polite"` 播报一句。
- 没有回调动画；`prefers-reduced-motion` 时关掉悬停过渡。

### 5.11 冷启动：起步卡、接管卡、接管简报（已确认，2026-10-30）

冷启动走「做法二」：先吃进用户手里已有的东西（邮箱、简历），由 AI 判断他在哪个阶段，不先问。

**起步卡**
- 条件：没连邮箱，也没有任何申请。按服务端数据判断出现和消失，不靠「看过了」标记。
- 内容：标题「从你手里有的开始」；连邮箱（QQ、163、Gmail 各一个入口）；「有简历？直接拖进输入框」；一行「什么都还没有，就说一件做过的事」。
- 和招聘概览上的起步块是同一个对象（第 3 节）。旧的「五步跑通第一条投递」和每日「还剩几步」提醒退役。

**接管卡**
- 历史邮件收完后出现在对话里，只出现一次；不自动跳页。
- 结构照回来卡：标题「替你接管了 N 家公司的申请」；最急的一件放最大（lg 海报 + 事由 + 期限大字 + 来源一行 + 「从最急的开始」）；下面几行事实（面试、笔试、已投递，带小签）；已结束只写数字。
- 末尾「看完整简报」打开接管简报页。

**接管简报（页面）**
- 顺序：替你接管了几家（来源邮箱、时间跨度、邮件数）→ 现在要你的事（最急一件 lg 海报，其余一行一件）→ 你现在大概在（阶段 + 依据，点一下能改，选中用墨色）→ 接管的申请（已投递 / 面试中 / Offer / 已结束，用小签；已结束只写数字，名单收起、点开才看且变淡）→ 没认出的邮件（可交给助理）。
- 准备期没东西可接管时，不写空白：写阶段与依据，再写下一步（提前批往年时间并注明以公告为准、经历库为空就拖简历或说一件事）。全页没有钢笔蓝。

## 6. UI 规则

### 6.0 文案只留帮他做这一步的（已确认，2026-11-05）

页面只呈现能帮他完成当前任务、理解当前数据或决定下一步操作的信息。业务规则（只存在本机、投出后撤不回、必填几项）不写成常驻说明，靠控件限制、字段级校验、提交前确认和失败反馈体现。重复标题、重复按钮含义的话、实现细节、接口约束、对当前操作没帮助的解释一律删。判据：删掉这句，他还能完成这一步吗——能就删。

### 6.1 颜色语义（已确认）

| 颜色 | 含义 |
|---|---|
| 钢笔蓝 | 只用于「要你动手」 |
| 墨色 | 已经发生 |
| 灰 | 还没轮到 |
| 红 | 只在出错时（沿用 `--danger`） |

卡片没有底色、描边、投影的外壳；只有卡组和系统通知是浮层。标题用文楷。

### 6.2 公司海报（已确认，2026-10-27）

一份申请的图形。

**上下分区**：上半是标志区，只有这里随品牌变化；下半是统一的浅底，岗位名和状态字所有海报一样，不随品牌、不随状态变色。

**标志分三类**：

| 类 | 判定 | 标志区 |
|---|---|---|
| 色块 | 标志自带品牌色块（如美团黄） | 铺满品牌色，标志放大 |
| 字标 | 其余官方标志或字标（DeepSeek、华为、字节…） | 浅底，标志居中，保留原色 |
| 名字 | 找不到标志的公司（多为小公司） | 浅底，用文楷写公司名 |

做到可用即可，不求每家都有标志。

**状态只看最底下一条**，位置固定：

| 状态 | 底条 |
|---|---|
| 排队 | 浅灰整条 |
| 在做 | 墨色短条 |
| 已投出 | 墨色整条 |
| 等你 | 钢笔蓝整条 |
| 换了新版 | 墨色短条，大海报右下加一个点 |

不用外框、不用填色表达状态。

**四档大小**：

| 档 | 尺寸 | 内容 | 用在哪 |
|---|---|---|---|
| lg | 168×200 | 标志区 + 岗位名 + 状态字 | 有期限、选时间、回来卡最急的一件 |
| md | 120×140 | 同上 | 批次卡目标岗位、要登录 |
| sm | 76×76 | 只有标志区 | 批次卡其余岗位 |
| xs（小签） | 64×28 | 只有标志区，横长 | 等你条、回来卡事实行、更正卡、缺信息的一片 |

最小一档也是标志或全名，不用首字（首字认不出是哪家）。一件事涉及多家时，等你条里用数字小签（如「20」）。

**单色版**（暂定）：预览里可切「标志单色」，把标志按深浅统一转成墨色；默认原色。

### 6.3 布局

- 等你条高 40px，紧贴输入框上沿；左边「等你 N」、小签、最早期限（钢笔蓝），右边「投出 x / y」和分段条。
- 卡组从等你条上方展开，最高 520px，内容超出可滚动；顶部「等你 n / N」、圆点、←→、收起。
- 要你的事左图右字：图在左，右边标题（文楷）、期限大字、来源一行、动作。

## 8. 数据（服务端要补的，暂定）

单位是申请，不再有 `flow_id`。前端只按下面两种描述渲染，不从工具私有字段里猜。

```ts
/** 一件要你的事。由 action_queue / handoff / deadline / inbox_item 派生，服务端合并后下发 */
interface AskView {
  id: string;
  kind: 'info' | 'login' | 'deadline' | 'slot' | 'review';
  application_ids: string[];   // 一个动作能解决的所有申请
  title: string;               // ≤ 12 字，如「证件号码」「九方云 · 在线测评」
  due_at?: string;             // 外部期限；没有则按挡住的申请数排序
  source?: { inbox_item_id: string }; // 来自哪封邮件
  field?: string;              // info：缺的字段，明文只在本机，不进模型上下文
  slots?: string[];            // slot：可选时间
  review?: { resume_version: string; changes: number; keyword_hit: [number, number] };
}

/** 公司标识 */
interface CompanyMark {
  company_id: string;
  logo_url?: string;           // 官方标志，缺省则用名字
  fill?: string;               // 色块类的品牌色
}
```

配套要求：

1. `AskView` 的合并规则（一个动作能解决）由服务端裁决，前端不自行合并。
2. 公司表补标志字段（`CompanyMark`）；来源、下载与兜底规则待定，没有就用名字。
3. 「这家我要看」「这类以后别问我」存在用户偏好里，跨会话。
4. 共用资料改动时，服务端返回「换成新版的申请」与「已投出的申请」两组 id，用于更正卡。
5. 岗位匹配分：现有 `match_json` 只用一条要求就算出 100%，修好前不展示，改用 JD 关键词覆盖数。

## 10. 怎么判断做得有没有用

- 一天里用户的点击次数（预览里有计数）：关键期一天投 20 家，目标是只为要你的事点。
- 回来后到处理完最急一件的时间。
- 同一件事被问的次数（目标 1：证件号码问一次管 20 家）。
- 「这类以后别问我」被点的分布（指向 AI 最该少打扰的环节）。
- 用户问「刚才那个呢」「XX 怎样了」的次数。

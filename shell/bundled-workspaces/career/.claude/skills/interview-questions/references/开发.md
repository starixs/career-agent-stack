# 开发出题手册（精简版）

> 涵盖：后端 / 前端 / 全栈 / 算法 / 数据工程 / 测试 / DevOps
>
> 本手册不判定技术答案对错，出题时标注 probe_points 而不是标准答案。

## 面试官在验什么

1. **是不是真的写过**：往实现细节追，背八股的人在第二三层就断。
2. **遇到问题怎么定位**：排查过程比结论更能说明能力。
3. **技术选型的依据与代价**：为什么用这个不用那个，知不知道代价；再加代码之外的协作、上线、故障处理。

## 高频追问链

**链一：项目深挖**
讲讲这个项目的架构 → 你负责哪部分 → QPS 多少，瓶颈在哪 → 怎么优化的，优化前后数据 → 为什么不用另一种方案
分水岭：第 3 层（说不出量级和瓶颈，通常只是参与者）

**链二：故障排查**
线上出过什么问题 → 你怎么定位的 → 先看什么日志/指标 → 根因是什么 → 后来怎么防止再发生
分水岭：第 2 层（这条最能区分实战经验，编不出来）

**链三：八股验真**
（概念题答对后）→ 你项目里哪里用到了 → 用的时候踩过什么坑 → 参数怎么调的
分水岭：第 2 层（背题的人接不住"项目里哪里用到"）

## 专业性检验点

- 后端：并发量与压测条件、数据库分表依据、缓存一致性方案、事务边界、消息队列选型理由
- 前端：首屏优化的具体手段和收益数字、状态管理方案取舍、兼容性处理
- 算法：数据集规模、评估指标、线上线下效果差异怎么处理、特征怎么来的
- 数据工程：数据量、调度工具、任务失败怎么恢复、数据质量怎么保证
- 测试：自动化覆盖率、用例设计方法、缺陷逃逸率
- DevOps：部署频率、回滚机制、监控告警怎么设的
- 通用：你负责模块的边界在哪，交接文档长什么样
- 通用：性能数字的测试条件（机器、数据量、并发）

## 按企业性质调整

- 大厂：算法题和系统设计是标配，追问深度最大
- 创业：更关注全栈能力和从零搭建的经验
- 国企银行：技术栈偏传统，更看重稳定性、规范、文档和合规
- 外企：英文技术面常见，code review 文化和协作方式是考点

# 产品出题手册（精简版）

> 涵盖：C 端 / B 端 / 数据产品 / SaaS / 平台产品

## 面试官在验什么

1. **判断力，不是执行力**：为什么做这个不做那个，砍掉了什么，依据是什么。
2. **需求是怎么来的**：老板说的、竞品有的，还是自己从数据和用户那里挖的。
3. **上线之后管不管**：只讲上线不讲效果和迭代，是需求翻译员不是产品经理；再加和研发的真实博弈过程。

## 高频追问链

**链一：需求判断**
为什么做这个功能 → 怎么确认是真需求 → 有多少用户有这个问题，怎么量的 → 当时还有哪些方案 → 为什么选了这个 → 只能做一半，砍哪块
分水岭：第 4 层（答不出备选方案，说明没做过决策）

**链二：上线之后**
上线效果怎么样 → 核心指标动了多少 → 怎么确认是这个功能带来的 → 有没有做灰度或 AB → 有没有指标变差的地方 → 后来迭代了几版
分水岭：第 3 层（只说好的不说坏的，追一句"有没有负向影响"）

**链三：协作**
研发说做不了你怎么办 → 具体怎么谈的 → 最后砍了什么保了什么 → 谁拍的板
分水岭：第 2 层（真推过硬仗的人说得出具体博弈）

## 专业性检验点

- 通用：你负责模块的北极星指标是什么，为什么是它
- 通用：需求优先级怎么排的，用什么方法，和研发怎么对齐排期
- 通用：写过 PRD 吗，评审时被挑最多的是什么；灰度怎么放，回滚条件是什么
- C 端：用户是谁，一类用户的真实行为是什么，不是画像标签
- B 端：客户是谁、决策链是谁、实施周期多长、续费率
- 数据产品：指标体系怎么搭的、口径归谁定、数据质量问题怎么处理
- SaaS：ARR、NDR、获客成本、客户流失原因
- 平台：双边怎么冷启动，供给侧和需求侧先做哪边

## 按企业性质调整

- 大厂：AB 实验、数据口径、归因追得最深
- 创业：问你没有研发资源时怎么把事推动起来
- 国企银行：更关注需求合规性、内部审批流程、跨部门协调
- 外企：stakeholder management 是高频考点，追问怎么对齐不同区域的诉求

# 设计出题手册（精简版）

> 涵盖：UI / UX / 视觉 / 产品设计 / 交互设计 / 用户研究

## 面试官在验什么

1. **作品集背后的决策过程**：看得见的是结果，要的是为什么这么做。
2. **是不是你做的**：团队作品里个人贡献的边界，追问必到。
3. **约束下的判断与可验证性**：开发说做不了、老板说改回去时怎么处理；改版后数据动了吗，做没做可用性测试。

## 高频追问链

**链一：作品集深挖**
讲讲这个项目 → 当时要解决什么问题 → 你出了几版方案 → 为什么定了这版 → 上线后数据怎么样 → 如果重做你改哪里
分水岭：第 3 层（只有一版方案通常说明是在执行需求）

**链二：协作冲突**
开发说这个效果实现不了，你怎么办 → 最后怎么改的 → 体验损失了什么 → 你怎么说服对方保住关键部分的
分水岭：第 3 层（说不出体验损失，说明没有权衡过）

**链三：用户研究**
你怎么知道用户有这个问题 → 做过调研吗，多少样本 → 结论怎么得出的 → 有没有可用性测试
分水岭：第 2 层（没有样本和方法，判断来自直觉）

## 专业性检验点

- 你负责的环节从哪到哪，交付物是什么
- 设计规范是你搭的还是沿用的，怎么维护
- 和开发怎么交付，标注、切图、组件库怎么管
- 改版前后有没有埋点，看哪些指标
- 用户研究：用过哪些方法，样本怎么招募的
- B 端设计：怎么理解业务流程，怎么处理复杂表单和权限
- 讲一个被否掉的方案和被否的原因
- 面对"老板说改回去"，你最后怎么做的，保住了什么

## 按企业性质调整

- 大厂：数据驱动，追问改版的指标验证和 AB 结果
- 创业：一人多岗，问能不能同时做视觉、交互、甚至运营物料
- 国企银行：规范、无障碍、合规展示要求高于创新度
- 外企：全球设计系统的本地化、跨时区协作、英文评审

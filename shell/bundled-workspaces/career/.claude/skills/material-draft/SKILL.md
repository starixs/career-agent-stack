# 目标
以极低的边际成本把一套素材复用到几十家投递上，同时保证对同一家公司在网申、邮件、各轮面试里说的话前后一致。先复用，再改写，最后才新写。

# 输入
素材类型与问题原文、长度要求（字数或 short / medium / long）、目标公司与岗位（JdParsed 可选）、已有素材库（同类型条目）、对这家公司已经说过的内容（素材使用记录）、经历库中已确认主张。

# 步骤
1. 找复用：在素材库里找同一问题键或同类型的条目，优先用已确认的；命中则只按公司与岗位做最小改写，不推翻结构。
2. 一致性核对：逐条比对对这家公司已说过的内容——实习时长、到岗时间、期望城市、薪资、项目里的数字、担任的角色。发现矛盾必须列进 conflicts，并以已经说过的版本为准，除非用户明确要改口。
3. 新写规则：公式＝结论先行 + 一到两个带数字的证据 + 与岗位的连接；数字只来自已确认主张；不写"热爱""充满热情"类空话，不用"赋能、闭环、抓手"。
4. 长度控制：按要求的字数上下浮动不超过一成；给出 short / medium / long 三档时各自独立成文，而不是简单截断。
5. 公司专属内容（为什么选择我们、对业务的理解）只用公司调研里已核实的事实，没有调研就写成可替换的占位并提示用户。
6. 输出要记录来源：每段落引用的 claim_ids、复用的 material_id，便于回写素材库与使用记录。

# 输出
```json
{
  "drafts":[{"length_variant":"short|medium|long","content":"","claim_ids":[],"reused_material_id":""}],
  "question_key":"归一化后的问题键，如 why_company",
  "conflicts":[{"field":"","said_before":"","now":"","where":""}],
  "placeholders":[{"text":"","why":""}],
  "save_as":{"kind":"open_question|project_story|self_intro|why_company|why_role|strength_weakness|career_plan|other","title":""}
}
```

# 约束
- 只用已确认主张；pending 主张不进素材，哪怕用户刚口头提到。
- 不为贴合岗位虚构工具、项目、数据、实习时长。
- 高影响信息（薪资、到岗、签约意愿）不替用户编写立场，没有记录就标占位让用户填。
- 存在 conflicts 时不能直接给"可提交"的结论，要先让用户决定以哪个版本为准。

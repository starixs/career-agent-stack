# 标签词表（完整版）

> 跨场统计要能用，前提是同一类问题每次都记成同一个词。本词表是受控的，归档时**只能从这里选**，不要自己造新词。
>
> **所有标签带命名空间前缀**，格式为 `命名空间:字段`。`counterfactual` 在内容问题和追问性质里都出现过，不带前缀就分不清是"用户答不出反事实问题"还是"面试官问了反事实问题"。
>
> 档案里写成 `命名空间:字段（中文展示名）`，前者用于统计，后者用于展示。

五个命名空间：

| 前缀 | 含义 |
|---|---|
| `content:` | 内容层面的问题 |
| `delivery:` | 表达层面的问题 |
| `language:` | 英文面试的语言问题 |
| `signal:` | 可观察的过程事实 |
| `probe:` | 面试官追问的性质 |

## content 内容问题

| 标签 | 中文展示名 | 什么情况用 |
|---|---|---|
| `content:metric-definition` | 数据口径 | 报了数字但说不清怎么算、分母是什么、统计周期多长 |
| `content:attribution` | 归因剥离 | 说不清成果里自己的部分和大盘、团队、季节因素怎么区分 |
| `content:personal-contribution` | 个人贡献不清 | 通篇"我们"，问到具体做了什么答不上 |
| `content:decision-rationale` | 决策依据 | 说不出当时有哪些备选方案、为什么选了这个 |
| `content:counterfactual` | 反事实回答不足 | 答不出"如果结果是反的会怎么办""重来一次改哪里" |
| `content:factual-gap` | 事实缺失 | 关键事实当场想不起来或从未掌握 |
| `content:role-motivation` | 求职动机 | 为什么投这个岗位、为什么选这家公司答得空泛 |
| `content:career-consistency` | 履历一致性 | 离职原因、时间线、职级说法前后对不上 |
| `content:company-research` | 公司功课 | 对公司业务、产品、近况了解不足 |
| `content:domain-depth` | 行业认知 | 行业观点经不起反问，或停留在公开报道层面 |
| `content:self-awareness` | 自我认知 | 缺点给的是伪缺点、失败题推责给外部 |
| `content:case-structure` | 案例框架 | case 题框架有明显缺口，或直接套通用模型 |
| `content:case-assumption` | 案例假设 | 假设不成立且没说明依据 |

## delivery 表达问题

| 标签 | 中文展示名 | 什么情况用 |
|---|---|---|
| `delivery:no-structure` | 无结构 | 讲述没有先后层次，听的人抓不到重点 |
| `delivery:excessive-context` | 背景过长 | 铺垫占了大半，真正做的事只讲了一点 |
| `delivery:missing-context` | 背景缺失 | 不交代前提直接进细节，对方听不懂 |
| `delivery:vague-language` | 表述含糊 | 全是形容词和抽象动词，没有具体名词和数字 |
| `delivery:answer-drift` | 答非所问 | 回答和问题不对应 |
| `delivery:excessive-length` | 时长失控 | 单题明显超时 |
| `delivery:filler-heavy` | 口头禅密集 | 语气词、连接词过多影响理解 |
| `delivery:tone-complaint` | 带负面情绪 | 评价前公司、前领导、前同事时带抱怨 |

## language 英文面试专用

> 只在英文面场次使用。语言问题和内容问题必须分开记，不能互相顶替。

| 标签 | 中文展示名 | 什么情况用 |
|---|---|---|
| `language:comprehension` | 没听清题 | 因为没听懂而答偏 |
| `language:fluency` | 表达卡顿 | 停顿、找词明显影响传达 |
| `language:word-choice` | 用词偏差 | 用词不准确或中式直译 |
| `language:we-overuse` | we 过多 | 个人贡献被集体表述盖住 |

## signal 可观察事实

> 只记录事实，不写解释。解释放在报告正文里，并按可观察事实 / 可能的解释 / 其他可能三层展开。

| 标签 | 中文展示名 |
|---|---|
| `signal:overtime` | 面试超时 |
| `signal:early-end` | 提前结束 |
| `signal:team-intro` | 主动介绍团队 |
| `signal:availability-ask` | 问到岗时间 |
| `signal:competing-offer-ask` | 问其他面试进度 |
| `signal:next-step-specific` | 给了具体下一步安排 |
| `signal:next-step-vague` | 结束语无具体信息 |
| `signal:interrupted` | 回答中途被打断 |
| `signal:reverse-qa-short` | 反问环节时间很短 |
| `signal:process-mention` | 提到体检、政审、档案等流程动作 |
| `signal:no-feedback` | 无反馈 / 结果未知（面试后超出常见周期仍无任何官方消息） |

`signal:no-feedback` 只记录"没有收到反馈"这一事实，不得据此推出拒绝原因；对应的结果字段用 `no_feedback_inferred`，见归档格式。

## probe 追问性质

> 同样密度的追问，性质不同含义完全不同，不能一律当成审问。

| 标签 | 中文展示名 | 特征 |
|---|---|---|
| `probe:clarify` | 澄清型 | 上一句有歧义，面试官在确认意思 |
| `probe:verify` | 验真型 | 在确认这件事是不是真的、是不是你做的 |
| `probe:counterfactual` | 反事实型 | 假设条件变了会怎么做 |
| `probe:challenge` | 挑战型 | 提出反方观点看能不能接住 |
| `probe:guide` | 引导型 | 用户卡住了，面试官在给台阶或提示方向 |
| `probe:routine` | 流程型 | 固定题本里的规定动作，与回答质量无关 |

**`probe:guide` 和 `probe:routine` 不计入丢分统计。**引导型追问通常说明面试官希望用户答好；流程型追问在结构化面试（国企、银行、部分校招）里是规定动作，用大厂标准解读会误判。

## 扩展规则

现有标签确实覆盖不了时可以新增，但要：

1. 先确认不是现有标签的同义说法
2. 必须带命名空间前缀，并同时给出中文展示名
3. 在本词表里补一行，保证下次还能对得上

不要在档案里直接写自然语言描述当标签用，写了就统计不出频次。

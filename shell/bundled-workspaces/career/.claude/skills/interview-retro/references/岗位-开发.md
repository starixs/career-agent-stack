# 开发岗复盘手册（精简版）

> 涵盖：后端 / 前端 / 全栈 / 算法 / 数据工程 / 测试 / DevOps
>
> 说明：本手册只复盘面试过程和表达层面，**不评判技术答案的对错**。用户需要确认某道技术题的正确答案时，说明这超出复盘范围，建议查阅权威资料或专业社区。

## 面试官在验什么

1. **是不是真的写过。**往实现细节追，背过八股的人在第二三层就断了。
2. **遇到问题怎么定位。**排查过程比结论更能说明能力。
3. **技术选型的依据。**为什么用这个不用那个，知不知道代价。
4. **代码之外。**协作、上线、故障处理、和产品怎么对齐。

## 高频追问链

**链一：项目深挖**
讲讲这个项目的架构 → 你负责哪部分 → QPS 多少、瓶颈在哪 → 怎么优化的、优化前后数据 → 为什么不用另一种方案
（分水岭在第三层：说不出规模和瓶颈，后面都无从验证）

**链二：故障排查**
线上出过什么问题 → 你怎么定位的 → 先看什么日志 / 指标 → 根因是什么 → 后来怎么防止再发生
（最能区分实战经验，编不出来；分水岭在第二层）

**链三：八股的验真**
（概念题答对后）→ 你项目里哪里用到了 → 用的时候踩过什么坑 → 参数怎么调的
（背题的人通常在第二层接不住）

## 专业性检验点（按方向）

- 后端：并发量、分表、缓存一致性、事务边界、消息队列选型理由
- 前端：首屏优化的具体手段和收益、状态管理取舍、兼容性处理
- 算法：数据集规模、评估指标、线上线下效果差异、特征来源
- 数据工程：数据量、调度工具、任务失败恢复、数据质量保证
- 测试：自动化覆盖率、用例设计方法、缺陷逃逸率
- DevOps：部署频率、回滚机制、监控告警设置

## 与企业性质叠加

- **大厂**：算法题和系统设计是标配，追问深度最大
- **创业公司**：更关注全栈能力和从零搭建的经验
- **国企 / 银行**：技术栈可能偏传统，更看重稳定性、规范、文档和合规
- **外企**：英文技术面常见，code review 文化和协作方式是考点

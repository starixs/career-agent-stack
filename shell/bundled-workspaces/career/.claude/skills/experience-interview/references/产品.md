# 产品类经历访谈手册

适用：C 端 / B 端 / 数据产品 / SaaS / 平台产品经理，以及产品助理、产品实习。

## 证据载体

| 载体 | 强度 | 说明 |
|---|---|---|
| PRD / 需求文档（带版本与评审记录） | 强 | 证明需求是你写的 |
| 原型文件（Axure / Figma 链接，含修改历史） | 强 | 可看出迭代过程 |
| 上线后数据看板、核心指标前后对比 | 强 | 没有数据的"上线"是半成品 |
| A/B 或灰度实验报告 | 强 | 证明效果归因 |
| 用户调研记录：访谈纪要、问卷原始数据 | 中 | 证明需求来源 |
| 需求评审纪要、排期表、JIRA / Tapd 记录 | 中 | 证明推动落地 |
| 竞品分析 / 产品体验报告 | 中 | 学生可当独立项目 |
| 自己做出来的小程序 / 公众号 / AI 工具 | 中 | 需附使用数据 |
| 课程项目的产品方案 PPT | 弱 | 需补分工与是否落地 |
| 口头的"我负责了这个功能" | 弱 | 一律标 pending |

## 评价指标

1. 核心指标变化：转化率 / 留存 / 活跃 / GMV 的前后值与口径
2. 需求来源的量化：多少用户反馈、多大比例有此问题、怎么测的
3. 上线规模：覆盖多少用户、几个端、几个版本
4. 迭代次数：上线后改了几版、每版解决什么
5. 推动范围：协调几个团队、多少人、几周上线
6. 取舍记录：砍掉了什么、为什么
7. B 端：客户数、实施周期、续费率、决策链长度
8. 数据产品：指标数量、口径归属、数据质量问题处理次数
9. SaaS：ARR / NDR / 获客成本 / 流失原因
10. 负向影响：有没有指标变差、怎么处理的（面试必问）

## 术语

- PRD：需求文档
- 北极星指标：核心目标指标
- 灰度：小范围放量
- 优先级模型：排需求方法
- KANO：需求分类模型
- 用户画像：用户特征概括
- 痛点：未被满足需求
- MVP：最小可行产品
- 需求池：待排期需求集
- 评审：需求 / 技术评审
- 排期：研发时间安排
- 埋点：行为数据采集
- 漏斗：转化分层
- 回滚条件：撤回上线标准
- 竞品：同类产品
- 决策链：B 端购买角色
- 实施：B 端交付过程
- 续费率：客户留存指标
- ARR：年度经常性收入
- NDR：净收入留存
- 需求翻译员：只传话不判断（贬义）

## 追问清单

**业务背景**
1. 这个产品 / 功能服务哪类用户、解决什么具体问题？当时业务处在什么阶段？
2. 需求是谁提的：老板、竞品、数据，还是你从用户那里挖出来的？

**规模数据**
3. 有多少用户有这个问题？你是怎么量的（问卷、访谈、数据）？
4. 上线覆盖多少用户、几个端？

**个人贡献**
5. PRD、原型、评审、推动上线这几步，哪些是你独立完成的？
6. 协调了哪些团队、多少人？研发说做不了的时候你具体做了什么？

**成果**
7. 上线后核心指标动了多少？和什么对比？有没有做灰度或 A/B？
8. 有没有指标变差的地方？后来迭代了几版？

**困难与解决**
9. 推动过程中卡在哪？最后砍了什么、保了什么、谁拍的板？
10. 评审时被挑最多的是什么？

**关键判断**
11. 当时有哪些备选方案？为什么没选另一个？
12. 如果只能做一半，你会砍哪块？当时是怎么判断的？

**降级问法**
- 「没做过产品」→ 自己做过小程序、公众号、用 AI 工具搭过东西吗？写过一份认真的竞品分析或体验报告吗？
- 「只是实习打杂」→ 有没有一个需求是你从头写文档、跟到上线的？哪怕很小。

> 本手册为通用归纳，具体口径以用户实际工作为准
